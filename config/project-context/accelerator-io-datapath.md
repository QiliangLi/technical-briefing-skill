# 加速器直连I/O与存储数据路径：项目判断卡

## 当前关注的问题

1. 方案改变了谁发起I/O、谁负责控制、数据经过谁以及发生几次复制中的哪一项？
2. CPU、Host DRAM、操作系统或驱动是否真正退出关键路径，仍保留哪些setup、权限、完成通知、错误处理和恢复职责？
3. 收益来自路径缩短、并发模型、请求粒度、控制器重构还是增加设备并行度？
4. IOPS、时延、带宽和功耗收益能否传导到GPU利用率、CPU消耗以及训练、推理、RAG、GNN、checkpoint或data loading的端到端指标？
5. 隔离、权限、故障恢复、多租户和部署成熟度是否足以支持生产使用？

## 值得进入本期判断的证据

优先保留能够还原真实路径和实验条件的证据：I/O发起者、control/data path、复制次数、Host DRAM流量、I/O大小分布、队列深度、GPU线程或请求并发、设备数量和互连拓扑，以及IOPS、吞吐、平均/尾时延、CPU/GPU利用率、功耗和端到端工作负载结果。性能数字应绑定baseline和条件；IOPS/W、IOPS/$或TCO必须给出计算口径。还要区分研究原型、开源实现、产品集成、送样、量产和规模部署。

## 判断边界

- 通用`O_DIRECT`、SPDK、io_uring、kernel bypass、zero-copy或文件系统优化，只有明确改变加速器与持久化存储之间的路径时才属于本专题。
- 仅有GPUDirect RDMA或GPU网络P2P、没有存储访问路径的工作不属于本专题。
- DPU、SmartNIC或IPU执行协议、元数据、安全、缓存、压缩或存储卸载时，优先归入DPU随路卸载。
- CXL内存池化、共享、一致性或远程内存语义优先归入内存语义、DSA卸载。
- GPU/NPU芯片内部访存、HBM、片上或封装互连优先归入AI芯片与加速器。
- NAND/HBF/NVM/HDD介质、FTL、耐久或介质主导的控制器协同优先归入存储介质与器件。
- 普通SSD容量、顺序带宽、PCIe代际、NAND层数或没有路径变化的benchmark不得仅凭厂商和关键词进入Deep。
- NVIDIA、Marvell、Micron是优先追踪对象，不是白名单；厂商名称命中不能代替机制、来源和证据判断。
