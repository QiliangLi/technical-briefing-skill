## Problem and evidence

风格 3 已经确定为更偏好的视觉方向，但参考图片本身不能直接作为实现合同：

- 图片只给出了 1586 × 992 桌面画布，没有定义其他宽度下的行为；
- 图片中的部分文字、数量和栏目是视觉示例，不能覆盖内容 Brief 和实际数据；
- 图片使用了较多衬线字体和紧凑表格，如果原样缩小到平板或手机，会明显降低可读性；
- 六张图片存在轻微的间距、导航和模块尺寸漂移，直接逐图硬编码会产生六套页面；
- 当前站点是静态 HTML、CSS 和 JavaScript，数据来自归档与长期知识 JSON，不应要求每期生成新的网页图片或装饰素材；
- 日报不保证对每条论文产生 workload、硬件、baseline 和完整实验条件，UI 不能反向制造额外分析成本。

因此需要一份介于设计图和代码之间的实现规格。它要让开发者能够先按像素还原参考图，再用同一套组件处理真实数据长度、字段缺失和不同屏幕宽度。

## Goals and non-goals

### Goals

- 以风格 3 为视觉基准，稳定复刻其编辑出版气质；
- 给出可以直接转写为 CSS Token、布局规则和组件 API 的尺寸；
- 六个页面共用同一套应用外壳、排版、表格、状态和卡片组件；
- 在 1586 × 992 下优先达到参考图的几何和视觉一致性；
- 吸收风格 2 对动态内容、可选字段、窄屏和触控操作的适应能力；
- 页面运行时只填充结构化数据，不调用任何文生图工具；
- 不因 UI 需要而提高日报的常规分析深度或 token 成本；
- 提供截图对照和回归验收办法，减少“看起来差不多”的主观实现。

### Non-goals

- 本文不改变 Roadmap、Idea、Claim、Assumption 或归档的数据语义；
- 本文不要求实现新的后端生成任务；
- 本文不照抄参考图中可能错误或虚构的业务内容；
- 本文不把页面做成报纸、PDF 阅读器或营销网站；
- 本文不引入实时动画、3D、Canvas 背景或按内容生成的插画；
- 本文不决定具体前端框架，当前实现可继续使用原生 HTML、CSS 和 JavaScript。

## Constraints and invariants

### 1. 信息与视觉的优先级

出现冲突时按以下顺序处理：

1. 数据合同和 UI 页面内容 Brief 决定“显示什么、含义是什么”；
2. 本文决定“组件怎样组织、不同尺寸怎样变化”；
3. 风格 3 图片决定 1586 × 992 下的视觉位置、比例和气质；
4. 风格 2 只提供内容伸缩和响应式参考，不带入它的深蓝顶栏、圆润插画和 SaaS 配色。

不得为了匹配图片而伪造字段，也不得因为数据为空而保留无意义的空白卡片。

### 2. 零运行时图片生成

- 六张风格图只用于开发对照，不能作为网页背景或切片素材；
- 每条论文、Idea、Roadmap、Claim 不拥有独立插画；
- 所有功能图标来自一套随代码提交的 SVG Sprite；
- Logo 使用固定 SVG；
- 时间线、Evidence Path、强度点阵和趋势线使用 HTML/CSS 或内联 SVG 由数据绘制；
- 不在数据 Schema 中加入 `image_prompt`、`topic_artwork`、`card_image` 等字段；
- 如果以后加入空状态插图，必须是一次性提交的固定资产，而不是每期生成。

### 3. 最小证据原则保持不变

- 页面只能展示归档和长期知识中已经存在的信息；
- workload、硬件、baseline、数据集和指标是可选信息；
- 可选内容不存在时，隐藏对应行或整个分组，不显示空占位；
- Evidence Explorer 可以提示缺少哪类证据，但不自动补写不存在的证据；
- Idea 尚未进入验证阶段时，不显示完整实验计划、运行参数和结果面板。

### 4. 只读公开边界

GitHub Pages 默认只读。页面不展示 Owner、预算、审批、私有实验结果和内部评论。参考图中的“添加证据”“新建实验”等操作若保留，只能作为进入外部工作流的链接；没有真实目标时应删除，不能做假按钮。

### 5. 浏览器和可访问性底线

- 桌面基准浏览器使用 Chromium；
- 正文与背景对比度不低于 4.5:1；
- 大号文字对比度不低于 3:1；
- 所有可交互元素具有可见的键盘焦点；
- 触控目标最小 44 × 44 px；
- 状态不能只靠颜色表达，必须同时有文字或图标；
- `html` 和 `body` 使用 `overflow-x: clip`，不能用 `hidden` 掩盖布局错误。

## Proposed design

### 1. 设计方向

页面应当呈现为一份正在持续更新的技术研究刊物，而不是常见的企业仪表盘。

用户实际看到的效果：

- 暖白、接近纸张但没有明显纹理的背景；
- 墨黑和深蓝灰文字，少量砖红与橄榄色标注状态；
- 大号衬线标题和克制的细分隔线；
- 正文、标签、按钮和表格使用清晰的无衬线字体；
- Claim、Decision、时间和来源像编辑批注与资料栏，但仍保持标准网页交互；
- 卡片接近资料框而不是悬浮气泡，圆角和阴影都很轻；
- 页面不包含照片、角色插画、3D 图标和每条内容独有的图片。

设计强度建议：风格辨识度 7/10，动态效果 1/10，信息密度 8/10。动态只用于 hover、focus、展开和路由切换反馈。

#### 明确排除的近似风格

- 不做暖米色加金色的复古奢华风；
- 不做整页衬线小字的报纸版面；
- 不做蓝绿橙三色 KPI 卡片式 SaaS 后台；
- 不做贴纸、胶带、纸张破损或明显噪点；
- 不做深色技术控制台；
- 不使用紫蓝渐变、玻璃卡片和发光边框。

### 2. 基准画布和全局坐标

#### 2.1 参考模式

参考图尺寸为 1586 × 992。实现时 Playwright 截图也必须使用：

```text
viewport: 1586 × 992
deviceScaleFactor: 1
font smoothing: Chromium default
page zoom: 100%
```

#### 2.2 桌面页面框架

| 项目 | 基准值 |
|---|---:|
| 顶部导航高度 | 72 px |
| 内容最大宽度 | 1540 px |
| 页面左右安全边距 | 24 px |
| 页面底部边距 | 32 px |
| 页面主间距 | 14 px |
| 区块内部间距 | 12 px |
| 页面标题区最小高度 | 145 px，首页为 160 px |
| 桌面侧栏宽度 | 312 px |
| 左右主栏间距 | 14 px |

```css
:root {
  --app-max: 1540px;
  --nav-h: 72px;
  --page-pad-x: 24px;
  --page-pad-y: 22px;
  --gap-1: 4px;
  --gap-2: 8px;
  --gap-3: 12px;
  --gap-4: 16px;
  --gap-5: 24px;
  --gap-6: 32px;
}

.app-inner {
  width: min(calc(100% - 48px), var(--app-max));
  margin-inline: auto;
}
```

#### 2.3 布局原则

- 1586 px 下，所有一级边线应落在参考图对应位置的 ±2 px 内；
- 主内容使用 CSS Grid，不使用绝对定位拼整页；
- 绝对定位只允许用于时间线节点、图标角标和局部装饰线；
- 所有 Grid 轨道使用 `minmax(0, 1fr)`，防止长标题撑破页面；
- 所有 Grid 和 Flex 子项显式设置 `min-width: 0`；
- 卡片高度默认由内容决定，参考图中的齐高只在同一行数据量相近时使用 `align-stretch`；
- 详情内容不能为了对齐被截断，列表摘要可以在桌面限制为 2 至 3 行。

### 3. 视觉 Token

#### 3.1 色彩

参考图接近纯白，但实现中使用轻微暖调，避免廉价的白底灰框。

```css
:root {
  --page: #f6f4ef;
  --surface: #fbfaf7;
  --surface-raised: #fffefb;
  --surface-muted: #f1eee7;

  --ink-1: #151b20;
  --ink-2: #343b40;
  --ink-3: #6e716f;
  --ink-inverse: #f8f7f2;

  --line-strong: rgba(28, 34, 38, 0.28);
  --line: rgba(28, 34, 38, 0.16);
  --line-soft: rgba(28, 34, 38, 0.09);

  --accent: #19334a;
  --accent-soft: #e8edf1;
  --accent-muted: #61778a;

  --positive: #536a3d;
  --positive-soft: #edf1e8;
  --warning: #b7792d;
  --warning-soft: #f8efe2;
  --negative: #bd5944;
  --negative-soft: #faece7;
  --neutral-state: #747b80;
  --neutral-state-soft: #eef0f1;

  --shadow: 0 1px 3px rgba(25, 31, 34, 0.045);
  --shadow-raised: 0 8px 22px rgba(25, 31, 34, 0.07);
}
```

使用规则：

- `--accent` 是产品识别色，导航选中、链接、主路径和重点数字使用它；
- 绿色只表示支持、进入或完成；
- 橙色只表示限制、待观察、待物化或证据不足；
- 红色只表示冲突、失效、反对或高风险；
- 蓝灰色表示中性信息、候选关系和辅助标签；
- 一个组件中最多出现一个品牌色和一个状态色；
- 不允许为了让卡片“更丰富”随机分配颜色。

#### 3.2 字体

要达到稳定的像素对照，生产环境应自托管中文字体。否则不同系统的宋体和黑体字宽会产生 1 至 6 px 的换行漂移。

```css
:root {
  --font-display: "Noto Serif SC", "Source Han Serif SC", "Songti SC", serif;
  --font-ui: "Noto Sans SC", "Source Han Sans SC", "PingFang SC",
    "Microsoft YaHei", system-ui, sans-serif;
  --font-mono: "SFMono-Regular", Consolas, monospace;
}
```

字体责任：

| 内容 | 字体 | 字重 | 大小 / 行高 |
|---|---|---:|---:|
| 产品名 | display | 700 | 25 / 32 px |
| 一级页面标题 | display | 700 | 52 / 1.08 |
| 详情对象标题 | display | 650 | 30 / 1.25 |
| 区块标题 | display | 650 | 21 / 28 px |
| 卡片标题 | display 或 UI | 650 | 16 / 23 px |
| 正文 | UI | 400 | 14 / 22 px |
| 表格正文 | UI | 400 | 13 / 19 px |
| 导航和按钮 | UI | 550 | 14 / 20 px |
| 标签与注释 | UI | 500 | 12 / 17 px |
| 大数字 | display | 550 | 34 / 1 |
| 日期和数量 | UI | 500 | 使用等宽数字 |

规则：

- 衬线字体只用于标题、大数字、区块标题和少量引文；
- 导航、按钮、状态、正文和表格必须使用无衬线字体；
- 标题使用 `text-wrap: balance`，正文使用 `text-wrap: pretty`；
- 所有标题设置 `overflow-wrap: anywhere` 和 `min-width: 0`；
- 日期、计数、Claim ID 使用 `font-variant-numeric: tabular-nums`；
- 不用全大写英文作为普遍栏目标题；
- 不使用人为增加的宽字距模拟杂志感。

#### 3.3 圆角、边框与阴影

| 层级 | 圆角 | 边框 | 阴影 |
|---|---:|---|---|
| 页面主资料框 | 6 px | `--line` | 无或 `--shadow` |
| 普通卡片 | 5 px | `--line` | 无 |
| 状态块、按钮、输入框 | 4 px | `--line` | focus 时使用外圈 |
| Badge | 3 px | 当前状态色 30% 透明度 | 无 |
| Tooltip、浮层 | 8 px | `--line` | `--shadow-raised` |

圆角必须明显小于风格 2。卡片依靠排版、边线和背景层次分组，不能依靠大圆角和大阴影。

#### 3.4 图标

- 统一 24 × 24 viewBox；
- 导航图标 18 px，卡片标题图标 18 px，空状态图标 32 px；
- 描边宽度 1.6 px，`stroke-linecap: round`，`stroke-linejoin: round`；
- 默认 `currentColor`，禁止图标自带渐变和多色填充；
- 只按语义映射图标，例如 Roadmap、Idea、Evidence、Archive、Claim、Assumption、Warning；
- 不按论文主题生成“GPU”“网络”“模型”等独有图标；
- 同一语义在全部页面使用同一图标。

### 4. 应用外壳

#### 4.1 顶部导航

桌面结构从左到右为：

```text
Logo + 产品名 | 首页 Roadmap Idea Hub Evidence 归档 | 弹性空白 | 搜索 | 用户入口
```

尺寸：

- 高度 72 px；
- 内部左右边距 24 px；
- Logo 46 × 58 px，Logo 与产品名间距 14 px；
- 导航项高度 72 px，左右 padding 18 px；
- 搜索框宽 400 至 560 px，高 42 px；
- 当前导航底线 4 px，位于导航底部；
- 顶栏底部分隔线 1 px；
- 顶栏保持单行，禁止导航文字换行。

顶栏使用 `position: sticky; top: 0; z-index: var(--z-nav)`。页面中若存在其他 sticky 区块，其 `top` 必须为 72 px，不能与顶栏重叠。

#### 4.2 搜索

- 桌面宽度由 `clamp(320px, 36vw, 560px)` 控制；
- 占位文字为“搜索 Topic、Roadmap、Idea、Claim、论文或来源”；
- 搜索结果使用 Dialog 或 Command Palette，不在顶栏内展开；
- 1024 px 以下缩为图标按钮；
- 搜索图标点击区域不小于 44 × 44 px。

#### 4.3 知识状态条

风格 3 中的三个状态框保持为共享组件：

- 归档最新；
- 知识物化；
- 落后多少期或部分失败。

桌面放在页面标题区右上角，单个高度 64 px，三项之间 12 px。平板时放在标题下方横向滚动或换行；手机时合并成一条状态摘要，点击展开详情。

状态条只表达系统状态，不用于展示 KPI。

### 5. 公共组件合同

以下组件名既是设计语言，也是建议的 CSS 类和渲染函数边界。

#### 5.1 `PageHeader`

内容槽：

```text
title
description?
breadcrumb?
knowledgeStatus?
actions?
```

规则：

- 标题和说明左对齐；
- 系统状态在桌面右对齐；
- 说明最长 72 个中文字符，超过后完整换行，不截断；
- 标题下方用一条强分隔线结束标题区；
- 页面标题不放在独立圆角卡片中。

#### 5.2 `EditorialSection`

用于承载一组紧密相关的资料。

- 背景 `--surface`；
- 1 px `--line` 边框；
- 6 px 圆角；
- 标题区高度 46 px，左右 16 px；
- 内容 padding 12 至 16 px；
- 标题区底部使用 `--line-strong`；
- 标题左侧图标可选，不得给每个区块强制加图标；
- `actions` 靠右，必须是明确动词。

#### 5.3 `MetricStrip`

首页和 Idea Hub 顶部统计使用连续横条，不使用六张独立悬浮卡片。

- 桌面为 4 至 6 个等分单元；
- 单元最小高度 112 px；
- 单元之间用竖线分隔；
- 每个单元最多包含图标、标签、数字和一行说明；
- 数字右对齐或与标签左边缘对齐，同一行保持一致；
- 768 px 以下转换为 2 列 Grid；
- 480 px 以下转换为单列紧凑列表。

#### 5.4 `StatusBadge`

```text
default | selected | positive | warning | negative | neutral | disabled
```

- 高度 24 px；
- 左右 padding 8 px；
- 字号 12 px；
- 不使用全填充高饱和色；
- 默认是浅背景、深文字、低透明边框；
- 必须保留状态文字，不能只显示彩色点。

#### 5.5 `DataTable`

- 表头高度 40 px；
- 普通行高 52 px，紧凑表可为 44 px；
- 文字和日期左对齐，纯数字右对齐；
- ID 和状态列固定宽度 80 至 120 px；
- 描述列使用 `minmax(220px, 1fr)`；
- 行 hover 只改变背景，不移动位置；
- 桌面不允许整个页面横向滚动；
- 平板优先隐藏低价值列并提供行详情；
- 手机转换为 `DefinitionListCard`，不把 7 列表格压缩到 320 px；
- 空状态显示“没有数据、原因、下一步”，加载态使用同高度骨架行。

#### 5.6 `DossierCard`

Idea、Candidate、Validation 和 Roadmap Track 的标准资料卡。

结构：

```text
header: id? + title + badges + menu?
summary?
fields: label/value rows
footer: nextAction? + links?
```

规则：

- 标题自然换行，不固定卡片高度；
- label 列宽在同一组件内固定；
- 不使用“图标 + 标题 + 两行字”的同质化宫格；
- 列表摘要最多 3 行，详情页不截断；
- `footer` 用 `margin-top: auto` 固定在同排卡片底部；
- 可选字段为空时整行消失，不渲染破折号占位。

#### 5.7 `Timeline`

- 时间顺序从上到下或从左到右，不能混用；
- 桌面详情侧栏使用纵向；Roadmap 主内容可以使用横向；
- 节点 12 px，当前节点 14 px；
- 主线 1 px；
- 日期使用等宽数字；
- 当前节点同时通过颜色、加粗和 `aria-current="step"` 表达；
- 时间项数量超过 6 时默认显示最近 5 项并提供展开。

#### 5.8 `EvidencePath`

固定语义顺序：

```text
原始来源 → 日报采用的 Claim → Roadmap Milestone 或 Idea Assumption
→ 系统综合判断 → Decision
```

- 桌面为 5 段横向流程；
- 箭头使用 CSS 或内联 SVG；
- 每段可以点击进入对应对象；
- 1024 px 以下转为纵向步骤；
- 关系状态通过线型、图标和文字共同表达；
- 不绘制无来源的推断边。

#### 5.9 `EditorialNote`

用于非理想状态、缺失证据、反对证据和方法说明。

- 普通提示使用 `surface-muted`；
- 证据不足使用 `warning-soft`；
- 冲突或来源失效使用 `negative-soft`；
- 标题不超过 18 个中文字符；
- 正文最多 3 行，更多内容通过详情展开；
- 不能用整块鲜红背景制造警报感。

#### 5.10 `SideRail`

详情页右栏宽度基准 312 px。

- 内部组件纵向间距 12 px；
- 默认不 sticky，只有“操作入口”可以在大屏固定于顶部导航下方；
- 侧栏信息不能复制主栏已有内容；
- 1024 px 以下移动到主内容之后；
- 不能隐藏唯一的来源、状态或下一步入口。

### 7. 响应式规则

#### 7.1 断点

| 区间 | 行为 |
|---|---|
| ≥ 1440 px | 参考模式，按 1586 × 992 还原 |
| 1280 至 1439 px | 保留桌面结构，压缩侧栏和间距 |
| 1024 至 1279 px | 双栏页缩窄侧栏，三栏页重排为两行 |
| 768 至 1023 px | 顶部导航精简，所有详情侧栏移至主栏之后 |
| 480 至 767 px | 单栏，导航进入菜单，表格转卡片 |
| 320 至 479 px | 最小支持宽度，单列紧凑阅读 |

#### 7.2 桌面弹性

```css
.two-column {
  display: grid;
  grid-template-columns: minmax(0, 1fr) minmax(280px, var(--rail-w));
  gap: 14px;
  align-items: start;
}

@media (max-width: 1023px) {
  .two-column {
    grid-template-columns: minmax(0, 1fr);
  }

```

- 不使用固定内容高度；
- 不使用 `overflow: auto` 制造卡片内部滚动，Evidence 图谱画布除外；
- 筛选器、Tabs 和按钮组允许换行，按钮文字本身不换行；
- 长英文 URL 和标识使用 `overflow-wrap: anywhere`；
- 页面不能依赖鼠标 hover 才能看到关键信息。

#### 7.3 手机降级

- 顶部导航变成 56 px 高的标题栏和菜单入口；
- 一级页面入口数量不超过 5 个；
- `PageHeader` 标题降为 34 px，区块标题降为 19 px；
- 状态条合并为单条摘要；
- Metric Strip 改为 2 列，再在 360 px 以下变为单列；
- 表格使用卡片化字段列表，而不是横向滚动；
- Evidence Path、Timeline 和 Milestones 全部改为纵向；
- 快速入口与次要操作移动到内容末尾；
- 在 320、375、414 和 768 px 四个宽度分别截图检查。

### 8. 数据填充合同

#### 8.1 组件只消费显示模型

底层归档数据不直接决定 DOM。每个页面先构造显示模型：

```js
{
  pageTitle,
  pageDescription,
  knowledgeStatus,
  metrics,
  primarySections,
  sideSections,
  optionalSections,
  sourceLinks
}
```

渲染组件只负责布局，不在组件内部推断业务含义。

#### 8.2 可选字段策略

| 情况 | 呈现规则 |
|---|---|
| 字段不存在 | 不渲染该行 |
| 一组字段全部不存在 | 不渲染该区块 |
| 有对象但证据不足 | 显示“证据不足”及缺失类型 |
| 对象为空 | 使用带原因和下一步的空状态 |
| 内容过长 | 列表摘要截断，详情完整展示 |
| 状态未知 | 使用 neutral 状态，不猜测 |
| 来源失效 | 保留来源记录并显示失效状态 |

#### 8.3 内容长度预算

这些是前端排版预算，不是上游生成硬限制：

| 内容 | 列表建议长度 | 详情建议长度 |
|---|---:|---:|
| 对象标题 | 18 至 34 字 | 最多 60 字后自然换行 |
| 一句话判断 | 36 至 72 字 | 不截断 |
| 卡片摘要 | 60 至 110 字 | 120 至 240 字 |
| 状态说明 | 24 至 56 字 | 最多 120 字 |
| Evidence Claim | 28 至 72 字 | 不截断 |
| 下一步动作 | 24 至 64 字 | 最多 120 字 |

内容超过预算时优先调整高度和换行，不能通过缩小到 12 px 以下解决。

### 9. HTML 与 CSS 组织建议

在现有原生实现中，建议按以下边界重构，而不是为六张图建立六套样式：

```text
site/
  index.html                 应用外壳和可访问性入口
  editorial-tokens.css       颜色、字体、间距、层级
  editorial-components.css   公共组件
  editorial-pages.css        六类页面网格
  app.js                     路由和数据加载
  workbench-view.js          显示模型与页面渲染
  assets/
    brand-mark.svg
    icons.svg                固定语义图标 Sprite
    fonts/                   自托管字体；像素对照验收时必需
```

建议的公共渲染函数：

```text
renderPageHeader(model)
renderKnowledgeStatus(status)
renderMetricStrip(metrics)
renderEditorialSection(section)
renderDossierCard(item, mode)
renderDataTable(columns, rows)
renderDefinitionCards(columns, rows)
renderTimeline(events)
renderEvidencePath(path)
renderEditorialNote(note)
renderSideRail(sections)
```

禁止：

- 在 HTML 中按页面复制粘贴相同导航；
- 在数据中携带 CSS 类名或颜色值；
- 根据数组索引随机分配卡片颜色；
- 用图片切片代替真实文本和表格；
- 用绝对坐标还原整个页面；
- 用组件空壳迫使上游补充没有必要的分析。

### 10. 交互状态

每个可交互组件至少实现：

- default；
- hover，仅精细指针设备；
- focus-visible；
- active；
- disabled；
- loading；
- empty；
- error。

动效限制：

- 颜色、阴影和背景过渡 120 至 180 ms；
- 页面路由切换只做 120 ms 的透明度变化；
- 不做滚动入场动画；
- 不做数字滚动、弹跳、呼吸、浮动和无限循环；
- `prefers-reduced-motion: reduce` 时关闭全部非必要过渡。

## Failure, recovery, and rollback

### 常见失败

| 失败 | 检测 | 处理 |
|---|---|---|
| 字体未加载导致换行漂移 | 截图标题和表格列宽变化 | 回退系统字体并标记视觉验收不通过 |
| 长标题撑破 Grid | 出现横向滚动 | 检查 `minmax(0,1fr)`、`min-width:0` 和 `overflow-wrap` |
| 缺字段留下空卡片 | 空白区块仍占高度 | 由显示模型移除整组 |
| 表格在手机不可读 | 需要横向拖动 | 转为 DefinitionListCard |
| 状态颜色失去语义 | 同一颜色代表多个含义 | 回到 Token 映射表修正 |
| 六个页面逐渐变成不同系统 | 导航、边距、标题尺寸不一致 | 只允许共享组件定义全局外壳 |
| 为填满组件增加上游分析 | 日报 token 或任务数量上升 | 删除非必要槽位，不扩充日常分析 |

### 回滚

- 视觉 CSS 应与数据逻辑分离；
- 实施期间通过单一顶层 class 或独立 stylesheet 切换新旧主题；
- 发现严重问题时只回退新主题引用，不回退数据合同和归档；
- 不删除旧样式，直到六个页面和四个响应式宽度全部验收通过。
