# Evidence 图谱 UI 生图 Brief

- Status: accepted
- Created: 2026-08-31
- Last updated: 2026-08-31

## 使用方式

这是一份给 UI 生图工具使用的视觉 Brief，不是开发规格。

推荐按以下顺序生成：

1. 复制“Prompt 1”生成桌面关系图主视图。
2. 选定主视图后，把它作为风格参考图，再生成 Archive Atlas、冲突状态和移动端。
3. 后三张图必须沿用主图的导航、配色、字体、节点、关系线和详情栏语言。
4. 使用文末验收清单筛掉深色霓虹图谱、无标签连线、全局毛线团和中文乱码。
5. 生成图片后再进入实现设计，不能直接根据图片推断数据 Schema 或构图规则。

主图结构固定为：

```text
左侧筛选 + 中央有界关系图 + 右侧来源详情 + 底部关系列表
```

页面中的可见文字必须使用简体中文。`Claim`、`Idea`、`Roadmap`、`Archive Atlas` 等已经在产品中使用的对象名可以保留英文，其解释、状态和操作文字必须使用中文。

## Problem and evidence

当前 Evidence Explorer 以可读的 Evidence Path 为核心，没有继续暴露原来的图谱视图。这个实现符合较窄的 UI 实现规格，但缺少了两个有价值的视觉任务：

- 查看来源、证据、Claim、Roadmap、Idea、Assumption 和 Decision 之间的明确关系。
- 按期次、Topic 和关键词浏览归档结构。

更完整的 Workbench 蓝图已经定义了 `Typed Relation Graph` 和保留的 `Archive Atlas`，并明确要求图谱是现有对象与关系的确定性投影，不能由浏览器猜测语义。

本文先定义 UI 参考图应该包含什么。完成图片并确认方向之前，不进入图谱实现。

## Goals and non-goals

### Goals

- 定义 Evidence Explorer 内关系图的完整页面结构。
- 定义节点、关系、来源详情、图谱控制器和列表降级。
- 延续已经实现的编辑部工作台视觉，不另起一套风格。
- 提供可以直接复制到生图工具的中文 Prompt。
- 默认显示一个对象附近的一跳关系，不绘制全局毛线团。
- 明确区分已确认、规则推导、冲突、未解析和候选关系。
- 图谱始终配套关系列表或 Evidence Path，不能成为唯一信息载体。

### Non-goals

- 本文不实现 Graph Builder、数据 Schema、渲染器或路由。
- 本文不决定使用 Cytoscape.js、G6、Sigma.js、D3 或其他库。
- 本文不引入图数据库，也不改变发布流程。
- 生图结果只是视觉参考，不能作为权威业务数据。
- 图谱不能制造不存在的 Claim、Milestone、实验结果或因果关系。
- 页面不使用照片、人物插画、3D 物体和装饰性运行时生图。

## Constraints and invariants

### 证据边界

- 实线关系只来自显式 ID 或已经发布的关系。
- 规则生成的关系显示规则名称和版本。
- 模型建议的关系必须标记为“候选关系 / 待确认”，使用虚线，并允许隐藏。
- 候选关系不能参与 Roadmap 和 Idea 的正式状态判断。
- Claim 或 Evidence Record 的详情必须能回到来源定位；如果没有精确定位，要直接说明。
- 来源事实、系统推理和决策必须通过文字、图标和形状共同区分，不能只靠颜色。
- 缺失对象使用“尚未物化”或“关系待解析”，不能生成一个看似合理的替代节点。

### 产品边界

- GitHub Pages 公开页面继续只读。
- 没有真实工作流目标时，不显示“添加证据”“确认关系”“创建实验”等假按钮。
- 默认只加载当前对象和一跳上下游。
- 可以继续展开第二跳，但必须显示节点上限和关系筛选。
- 桌面关系图是 Evidence Path 和关系列表的补充，不是替代。
- 移动端默认显示纵向证据链和列表，不压缩桌面图谱画布。

### 生图数据边界

- 文档中的示例内容只用于排版。
- 当前仓库尚未物化的 Claim 必须显示“示例 Claim”或“待物化”。
- 不虚构置信度百分比、性能提升、节点总数或实验结果。
- 可以使用真实期次和真实对象名称；其余数字尽量用定性状态代替。

## 中文文字生成策略

生图模型对长中文和密集表格的稳定性有限，因此参考图采用“短中文标签优先”的策略。

### 必须清晰生成的文字

- 页面标题和一级导航。
- 四个视图 Tab。
- 节点类型与关系类型。
- 当前聚焦对象的短标题。
- 详情栏分组标题。
- “待确认”“待物化”“证据存在冲突”等关键状态。
- “打开原文”“打开日报”“查看证据链”等操作。

### 可以结构化占位的文字

- 超过 24 个汉字的来源标题。
- Claim 的完整长句。
- URL、来源定位和版本号。
- 详情栏内超过两行的解释。
- 关系列表中的次要行。

生成参考图时，长文本可以缩写成两行以内，但不能使用乱码、无意义英文或 Lorem Ipsum。需要精确的长文案将在真实 UI 实现时写入。

## Design direction

这是一个日常使用、信息密度很高的产品页面。它应该像“技术研究资料册中嵌入了一块关系拓扑工作区”，而不是企业数据大屏，也不是未来感 AI 知识图谱。

用户应该看到：

- 暖白色页面和面板。
- 墨黑与深蓝文字。
- 砖红表示挑战或冲突。
- 橄榄绿表示支持或已确认进展。
- 页面标题和区块标题使用中文衬线字体。
- 控件、节点、标签和表格使用清晰的无衬线字体。
- 细分隔线、4 至 6 px 小圆角和近乎不可见的阴影。
- 淡色图谱画布，只带很轻的坐标网格或套准标记。
- 节点像研究标签和资料条，而不是漂浮气泡。
- 关系线有明确箭头、文字标签和线型。
- 不使用渐变、发光、玻璃卡片、霓虹、粒子和模拟景深。

建议视觉强度：风格辨识度 7/10，动态效果 1/10，信息密度 9/10。

这是现有 Workbench 的同级页面，不做新的配色和导航范式。页面内容不需要照片或插画，图谱本身就是视觉主体。

## Master screen: Typed Relation Graph

### 桌面结构

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 上下文条：当前对象、可见范围、知识水位、关系图例                           │
├───────────────┬─────────────────────────────────────────────┬──────────────┤
│ 左侧筛选      │ 中央图谱画布                                │ 右侧详情     │
│ 248 至 272 px │ minmax(0, 1fr)                              │ 336 至 360 px│
│               │                                             │              │
│ 对象搜索      │ 左到右的局部拓扑                            │ 当前节点     │
│ 节点类型      │ 默认一跳，可展开第二跳                      │ 来源与定位   │
│ 关系类型      │                                             │ 条件与影响   │
│ 时间范围      │ 画布工具与小地图                            │ 来源链接     │
│ 候选关系      │                                             │              │
├───────────────┴─────────────────────────────────────────────┴──────────────┤
│ 关系列表预览和无障碍降级                                                   │
└────────────────────────────────────────────────────────────────────────────┘
```

- 外部间距 12 至 14 px。
- 左右面板使用暖白抬升面和细边线。
- 图谱画布占工作区约 58% 至 62%。
- 图谱画布允许独立缩放和平移。
- 详情栏使用与选中节点一致的类型图标和标题。

### 上下文条

显示：

- 当前 Idea：`把热前缀当作可复制对象，联合路由与跨节点 KV 放置`
- 对象状态：`Idea · observing`
- 范围：`上游与下游 1 跳`
- 可见关系：`声明 · 支持 · 影响 · 导致`
- 知识水位：`知识物化至 2026-08-17`
- 已确认、冲突和候选关系的紧凑图例

这里不使用大号 KPI 数字。

### 左侧筛选

依次包含：

1. 搜索框：`搜索 Claim、Idea、Roadmap 或来源`
2. 当前 Idea 摘要和 `observing` 状态
3. 节点类型：来源、证据记录、Claim、Roadmap、Idea / Assumption、Decision
4. 关系类型：声明、支持、挑战、限定、影响、导致
5. 时间范围
6. 深度控制：`1 跳`选中，`2 跳`可用
7. `显示候选关系`开关，默认关闭
8. `最多显示 40 个节点`设置

控件紧凑、左对齐，用分隔线组织。不要把每组筛选做成独立悬浮卡片。

### 图谱画布

关系图使用从左到右的方向布局：

```text
来源 / 归档条目
    ↓ 声明或提供
证据记录 / Claim
    ↓ 支持、挑战或限定
当前 Idea 或 Roadmap 对象
    ↓ 影响或导致
Assumption / Milestone / Decision
```

主图显示 14 至 20 个可读节点。选中的 Claim 位于中央偏左。一跳关系保持清晰，无关节点降低到约 25% 的视觉强调。

主图示例节点：

- 来源：`PTStore：借鉴 CDN 复制可复用 KV 前缀`
- 来源：`TensorCast：统一张量生命周期`
- 证据记录：`2026-08-11`
- Claim：`示例 Claim · 热前缀复制提高跨节点复用`
- 当前 Idea：`热前缀复制与跨节点 KV 放置`
- Roadmap 分支：`KVCache 感知的网络与带宽调度`
- Assumption：`复制收益高于目录与同步成本`
- Unknown：`多租户隔离和前缀隐私边界`
- Decision：`2026-08-11 · 新增证据`

“示例 Claim”必须保留该标记，因为当前物化数据还没有对应的一等 Claim 对象。

### 节点视觉语法

| 节点类型 | 形状与表面 | 次要信息 |
| --- | --- | --- |
| 来源文档 | 紧凑文档卡，带文档图标 | 发布方、日期 |
| 证据记录 | 窄矩形资料条，带日期标记 | 日报期次、来源级别 |
| Claim | 加长圆角矩形，描边最清晰 | 来源事实 / 系统推理、核验状态 |
| Roadmap Track / Milestone | 方正资料签，顶部短线 | Topic、分支、状态 |
| Idea | 稍大的编辑部资料卡，深蓝标题 | Idea 类型、状态 |
| Assumption / Unknown | 小型标签卡 | 已支持 / 受挑战 / 未知 |
| Decision | 小菱形标记连接日期文字 | 日期、决策类型 |
| 未解析端点 | 淡色虚线矩形 | 尚未物化 / 关系待解析 |

候选节点使用虚线描边和“待确认”。选中节点使用 2 px 深蓝描边和小型套准角，不使用发光。

### 关系线视觉语法

| 关系 | 视觉形式 | 中文标签 |
| --- | --- | --- |
| `asserts / provides` | 深蓝细实线箭头 | 声明 / 提供 |
| `supports` | 橄榄绿实线箭头 | 支持 |
| `challenges / contradicts` | 砖红实线箭头，带冲突图标 | 挑战 / 反对 |
| `narrows` | 琥珀色短虚线 | 限定 |
| `informs` | 深蓝灰细线 | 影响 |
| `caused` | 较粗深蓝箭头 | 导致 |
| 候选关系 | 灰色虚线 | 待确认 |
| 未解析关系 | 点线，在淡色端点前停止 | 关系待解析 |

颜色不能成为唯一区别，必须同时使用文字、线型和图标。

### 画布控制器

画布右上角使用一组紧凑工具：

- 适应画布
- 缩小
- 当前缩放比例
- 放大
- 重置聚焦
- 展开一跳

右下角可以放一个淡色小地图。左下角显示：`关系图仅显示当前对象附近的有界关系`。

### 右侧详情栏

主图选中“示例 Claim”，详情栏依次展示：

1. 身份：Claim、示例 Claim、待物化
2. 陈述：`热前缀复制能够提高跨节点复用，并减少重复 Prefill。`
3. 分类：来源事实 / 系统推理 / 决策
4. 条件：硬件、负载、baseline、适用范围；缺失时显示`适用条件仍不完整`
5. 来源：来源标题、来源定位、日报期次、生成方式或规则版本
6. 影响：关联 Idea、Roadmap 分支、Decision
7. 操作：`打开原文`、`打开日报`、`查看证据链`

详情栏使用定义列表和细分隔线，不堆叠彩色卡片。

### 底部关系列表

桌面图片底部应露出关系列表的表头和首行，让用户看出图谱不是唯一信息形式。

列为：

- 来源对象
- 关系
- 目标对象
- 确认状态
- 来源
- 更新时间

行高约 44 至 48 px。图中选中的关系与表格选中行使用同一浅深蓝背景。

## Secondary screen: Archive Atlas

Archive Atlas 必须明确标记为`结构浏览视图`，不能暗示证据语义。

### 布局与控制

- 沿用相同导航、页头和 Tab，选中 Archive Atlas。
- 左侧控制栏 240 至 264 px。
- 中央为大画布，右侧为 320 至 344 px 的条目详情。
- 范围：最新一期 / 全部归档。
- 分组：按 Topic / 按关键词。
- 筛选：期次、Topic、关键词、深度 / 简要 / 雷达。
- 固定说明：`这里的连接表示归档结构和关键词聚合，不表示支持或因果关系。`

### Atlas 图谱

Topic 模式使用三条有序泳道：

```text
日报期次 → Topic → 归档条目
```

参考图显示：

- 期次：08-10、08-11、08-17、08-29
- Topic：状态感知网络、TPN；Agent 语义加速；跨域传输
- 条目：PTStore、TensorCast、AAFLOW+、LMCache
- 一个聚合节点：`+6 简要`
- 右侧详情：标题、角色、Topic、期次、来源地址和跨期出现记录

Atlas 关系线统一使用中性深蓝灰。线宽可表示数量，但必须同时显示数量文字。不要使用“支持”“挑战”“因果”等语义颜色。

## State screen: conflict and candidate edges

状态图用于补充主图难以同时表达的特殊状态：

- 中央选中一个 Assumption。
- 一条橄榄绿“支持”关系。
- 一条砖红“挑战”关系。
- 一条琥珀色“限定”关系。
- 一条灰色虚线“待确认”候选关系。
- 状态标签：`证据存在冲突`。
- 未解析端点：`缺少真实硬件验证`。
- 右侧详情对照支持证据和反对证据，并显示来源。
- 顶部保留隐藏候选关系的开关。

冲突状态保持克制，不使用大面积红色警告卡。

## Mobile reference

移动端参考尺寸为 `390 × 844`。

不要缩小桌面图谱画布，按以下任务顺序排列：

1. 56 px 顶栏，标题`关系图`
2. 紧凑知识水位摘要
3. 单行横向滚动的视图 Tab
4. 当前 Idea 卡片
5. 纵向`证据路径`
6. 打开底部筛选层的`筛选关系`按钮
7. 当前节点详情，使用页面内区块或底部抽屉
8. 关系列表卡片
9. 次要操作：`在桌面查看关系图`

纵向路径沿用桌面节点图标、语义色、线型和关系标签。所有触控区域至少 44 × 44 px，按钮文字不换行，页面不能横向溢出。

## Image-review checklist

只有同时满足以下条件，生成图片才可进入下一轮：

- 页面明显属于现有编辑部工作台，不是独立的新设计。
- 所有主要可见文字为简体中文，中文没有明显乱码。
- Evidence Explorer 和当前视图在首屏清晰可见。
- 图谱是最大工作区，但没有挤掉筛选和来源详情。
- 节点类型同时通过形状、图标和文字区分。
- 关系类型同时通过标签和线型区分，不能只靠颜色。
- 不阅读所有节点也能理解当前节点和一跳关系。
- 右侧详情显示来源与影响，不是泛化元数据。
- 候选关系明确标记为待确认并可隐藏。
- Archive Atlas 明确说明结构关系不等于证据语义。
- 未物化 Claim 仍显示“示例 Claim”或“待物化”。
- 图谱不是唯一信息载体，画面中能看到路径或关系列表。
- 不包含深色霓虹、玻璃卡片、渐变、漂浮球体或全局毛线团。
- 移动端使用纵向路径和列表，没有缩小桌面画布。

## Failure, recovery, and rollback

最主要的失败是图片看起来漂亮，但表达了错误的图谱语义。以下情况必须重新生成：

- 关系线没有标签。
- 把相似度或候选关系画成已确认事实。
- 隐藏来源定位。
- 默认展示全局毛线团。
- 没有路径或列表降级。
- 冲突和置信状态只靠颜色表达。
- 与现有 Workbench 视觉明显不一致。
- 中文导航、按钮或节点标题出现大面积乱码。

本文仅为设计文档，回滚只需放弃生成的参考图，不影响运行时状态和已发布数据。
