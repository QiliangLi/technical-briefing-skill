## Problem and evidence

页面内容已经与视觉风格分离。下一步需要使用同一份页面内容生成风格迥异的 UI 方案，以便只比较审美、气质和可读性，不让不同示例数据干扰判断。

根据 `gpt-image-2-style-library`，所有方案统一以 `UI Screenshot System` 为基础模板，再引入不同的辅助模板和视觉语言。这样既保留真实产品界面的完整性，也能形成小红书卡片、商务可爱、编辑出版、暗色技术、手账、粗野主义、3D 潮玩和东方纸本等明显差异。

## Goals and non-goals

### Goals

- 提供 8 个差异足够大的 Style Brief；
- 每个 Brief 可以与任意页面内容组合；
- 每个 Brief 包含模板来源、视觉关键词、具体规则和可复制提示词；
- 使用同一页面和数据进行第一轮风格对比；
- 风格变化不改变内容含义和证据关系。

### Non-goals

- 本文不重复页面内容；
- 不决定最终采用哪一种风格；
- 不要求一次生成全部页面；
- 不允许风格装饰压过文字、状态和证据关系。

## Constraints and invariants

### 共同模板

- 主模板：`UI Screenshot System`
- 模板 ID：`ui-screenshot-system`
- 分类：UI & Interfaces
- 场景：Tech、Social
- 参考案例：case 17、case 2、case 4

### 组合方式

每次生成只选择一个页面和一个 Style Brief：

```text
UI 页面内容 Brief 中的某一页
+ 本文中的一个 Style Brief
= 一张完整 UI 设计图
```

### 第一轮对比协议

第一轮统一生成“Idea 详情页”，因为它同时包含标题、Origin、状态、Assumptions、证据和验证建议，最容易看出不同风格是否仍能承载复杂信息。

所有方案保持：

- 相同页面内容；
- 相同中文示例；
- 相同画面比例；
- 相同信息完整度；
- 一张图只展示一个完整页面；
- 不生成设备样机和多屏 Moodboard。

推荐第一轮输出比例为 16:10。比例只是对比约束，不代表最终产品必须采用该比例。

### 通用生成指令外壳

复制下面的通用指令，再追加一个 Style Prompt。将方括号中的页面名称替换为本次要生成的页面。


## Proposed design

### Style 01：小红书软萌知识卡片

#### 定位

像高质量小红书知识博主制作的可爱信息卡片，但仍然是一张完整的 Web 产品界面。适合降低技术内容的距离感，让 Roadmap、Idea 和证据关系更容易被非专业用户理解。

#### 模板组合

- 主模板：`ui-screenshot-system`，case 17 / 2 / 4
- 辅助模板：`infographic-engine`，case 334 / 1 / 8
- 辅助模板：`illustration-art-style`，case 346 / 6

#### 视觉关键词

```text
小红书知识卡片、软萌、轻卡通、贴纸、手绘箭头、圆润、奶油感、清爽、信息图、年轻、亲和
```

#### 风格规则

- 使用奶油白、蜜桃粉、珊瑚橙、浅天蓝、嫩绿色等轻柔配色；
- 信息组像知识卡片或便签，但保持清晰的页面层级；
- 状态标签可以使用胶囊、贴纸、小印章或手绘圈注；
- 允许少量星星、灯泡、放大镜、文件夹等小型手绘图标；
- 用短标题、编号和手绘箭头增强阅读路径；
- 插画只承担解释和导航作用，不遮挡数据；
- 可爱但不幼儿化，不使用大量表情包和角色占据主体。

#### 避免

- 不要做成纯社交媒体海报；
- 不要把整个页面拆成大量大小不一的贴纸；
- 不要使用过多粉嫩渐变、爱心和无关装饰；
- 不要让中文看起来像手写乱码。

#### 可复制 Style Prompt

```text
视觉风格采用高质量小红书知识卡片风。界面亲切、软萌、轻卡通，但仍然是真实可开发的桌面 Web 产品。使用奶油白底色，搭配蜜桃粉、珊瑚橙、浅天蓝和嫩绿色。信息组像整齐的知识卡片和便签，使用圆润边角、轻微纸张层次、胶囊标签、小印章、手绘箭头和少量解释性贴纸。标题和数据必须清晰可读，证据路径必须明确。保持清爽留白，避免幼儿化、表情包堆叠和社媒海报感。
```

### Style 02：商务可爱 Friendly Corporate

#### 定位

面向企业内部和管理者的友好型商务产品。比传统仪表盘更温和、更可爱，但仍然稳重、可信、适合长期使用。

#### 模板组合

- 主模板：`ui-screenshot-system`，case 17 / 2 / 4
- 辅助模板：`brand-identity-package`，case 354
- 辅助模板：`personalized-beauty-report`，case 353，仅借用柔和报告层级

#### 视觉关键词

```text
商务可爱、友好企业级、柔和专业、品牌化、温暖、圆润、克制、可信、轻盈、现代 SaaS
```

#### 风格规则

- 主色使用深蓝、象牙白，辅以薄荷绿、雾紫或杏色；
- 组件圆润但不过分膨胀，阴影柔和、边界清楚；
- 使用简洁几何图标和少量友好插画；
- 重要结论保持商务报告式层级；
- 风险和冲突表达明确，但避免强烈警报感；
- 可爱感来自比例、圆角、图标和微妙配色，不依赖卡通人物。

#### 避免

- 不要传统银行后台或 ERP 风格；
- 不要过度粉嫩；
- 不要大面积儿童插画；
- 不要玻璃拟态和大量发光渐变。

#### 可复制 Style Prompt

```text
视觉风格采用 Friendly Corporate 商务可爱风。界面适合企业技术负责人长期使用，专业可信但不冷漠。使用深蓝与象牙白作为基础，辅以薄荷绿、雾紫和杏色。组件有克制圆角、柔和边界和清楚层级，图标简洁友好，可加入少量几何插画。重要判断像现代商务报告，状态和风险清楚但不过度警报。可爱感来自圆润比例、柔和色彩和友好细节，不使用幼儿卡通人物。
```

### Style 03：独立杂志编辑部

#### 定位

像一本高质量技术杂志、研究刊物或独立编辑部制作的数字出版物。强调判断、引用、脚注和阅读节奏，适合突出技术情报的内容价值。

#### 模板组合

- 主模板：`ui-screenshot-system`，case 17 / 2 / 4
- 辅助模板：`document-publishing`，case 360
- 辅助模板：`poster-layout-system`，case 345 / 5 / 10

#### 视觉关键词

```text
独立杂志、编辑部、研究刊物、数字出版、社论、脚注、纸张、克制、权威、内容优先
```

#### 风格规则

- 使用暖白纸张、黑色正文、深红或墨蓝强调；
- 大标题具有出版物气质，正文与注释层级明显；
- Claim、来源和 Decision 像引文、脚注、边注或编辑批注；
- 使用细线、编号、章节标识和清晰的栏目节奏；
- 图标尽量少，让文字和证据成为主角；
- 页面可以有明显的编辑观点区和资料区，但保持产品导航可用。

#### 避免

- 不要做成 PDF 或纯报纸版面；
- 不要使用密集小字；
- 不要复古到影响技术感；
- 不要使用大面积装饰图片。

#### 可复制 Style Prompt

```text
视觉风格采用高质量独立技术杂志与数字编辑部风格。使用暖白纸张质感、黑色正文、深红或墨蓝强调。标题具有出版物层级，Claim、来源和 Decision 像清晰的引文、脚注与编辑边注。使用细线、编号、章节标识和克制留白，强调内容、判断和证据，而不是图标和装饰。界面仍然是完整可交互的 Web 产品，不要变成纯报纸或 PDF 页面。
```

### Style 04：深色技术情报台

#### 定位

面向技术专家的深色分析工具，像安静、精确的情报台或工程观测系统。强调关系、状态和追踪，不做夸张赛博朋克。

#### 模板组合

- 主模板：`ui-screenshot-system`，case 17 / 2 / 4
- 辅助模板：`concept-product-breakdown`，case 370 / 361
- 辅助模板：`infographic-engine`，case 334 / 1 / 8

#### 视觉关键词

```text
深色技术、情报台、工程分析、精密、低照度、层级清楚、数据追踪、专业、克制
```

#### 风格规则

- 使用炭黑、深蓝灰作为基础，电蓝、青色、琥珀色作为状态强调；
- 关系线、时间、状态和来源标记清晰；
- 可以使用细网格、轻量终端感和等宽数字，但正文仍易读；
- 发光仅用于当前选中对象或关键路径；
- 强调 Evidence Path、时间线和状态差异；
- 保持安静、精密，不追求视觉刺激。

#### 避免

- 不要赛博朋克城市、霓虹雨、HUD 圆环和全息地球；
- 不要大量发光边框；
- 不要终端代码占据页面；
- 不要黑底低对比小字。

#### 可复制 Style Prompt

```text
视觉风格采用深色技术情报台。使用炭黑和深蓝灰作为背景，电蓝、青色和琥珀色用于关键状态。界面安静、精密、专业，关系线、时间、证据状态和当前选择非常清楚。可以有轻微工程网格和等宽数字，但正文保持高可读性。只让关键证据路径轻微发光。不要赛博朋克城市、HUD 圆环、全息地球、霓虹雨和大面积发光。
```

### Style 05：研究手账与贴纸笔记

#### 定位

像研究者长期维护的技术手账、实验笔记或项目观察册。比小红书风更安静、更个人化，强调时间积累、批注和线索连接。

#### 模板组合

- 主模板：`ui-screenshot-system`，case 17 / 2 / 4
- 辅助模板：`illustration-art-style`，case 346 / 6
- 辅助模板：`document-publishing`，case 360

#### 视觉关键词

```text
研究手账、笔记本、纸张、索引标签、便签、铅笔批注、胶带、日期印章、温暖、长期积累
```

#### 风格规则

- 使用米白纸张、浅网格或点阵背景；
- 使用索引标签、日期印章、便签和克制的胶带元素；
- 关系可以像铅笔连线、下划线或批注箭头；
- 信息排列仍然整齐，不能真的像凌乱桌面；
- 允许少量手绘技术符号和边注；
- Roadmap 的时间感和 Archive 的积累感应特别突出。

#### 避免

- 不要真实扫描件的污渍和严重褶皱；
- 不要大量倾斜纸片；
- 不要手写全部正文；
- 不要让胶带、贴纸遮挡数据。

#### 可复制 Style Prompt

```text
视觉风格采用研究手账与技术笔记本风格。使用米白纸张、轻微点阵或网格、索引标签、日期印章、便签、克制胶带和少量铅笔批注。关系线像清晰的手绘箭头或下划线，页面传达长期积累和研究观察感。信息必须保持整齐可读，正文仍使用清楚的印刷字体。不要做成凌乱桌面、扫描旧纸或全部手写的手账拼贴。
```

```text
3D 潮玩、软陶、积木、微型实验室、圆润、空间感、可爱、模块化、数据物件、品牌感
```

#### 风格规则

- 保持同一种材质和光线语言。

#### 避免

- 不要让公仔占据页面主体；
- 不要生成玩具包装盒；

## Compatibility and migration

- Style Brief 只影响视觉，不改变页面内容、对象关系和证据语义；
- 任一风格都可以单独替换，不需要修改 UI 页面内容 Brief；
- 最终风格可以吸收两个方向，但必须先明确主风格和辅助风格，避免无边界混搭；
- 选定风格前不修改后端 Schema 和生产页面。

## Failure, recovery, and rollback

- 生图结果变成海报或 Moodboard 时，重新强调 `UI Screenshot System` 和完整产品页面；
- 生图结果文字过多时，减少可见示例文字，不删除核心信息组；
- 风格装饰影响可读性时，降低装饰比例，不改变内容；
- 不同风格使用了不同页面数据时，使用共用内容 Brief 重新生成；
- 混合风格失败时回到单一 Style Brief，不继续追加形容词。

## Verification

每个风格方案必须满足：

- 一眼可看出与其他方案的风格差异；
- 仍然像真实可开发的产品界面；
- 中文标题、状态和证据关系可读；
- 页面内容与共用内容 Brief 一致；
- 风格没有改变来源事实、系统综合和内部判断的含义；
- 不因装饰要求增加论文分析字段；
- 同一风格扩展到首页、Idea、Evidence 和 Archive 后仍保持一致。

## Documentation impact

- 本文与 UI 页面内容 Brief 配套使用；
- 选定方向后，将获选风格整理为单一当前 Style Contract；
- Workbench Blueprint 只在风格选定后更新布局和交互；
- 未获选 Style Brief 保留为设计探索，不进入当前实现契约。
