# 含插画版邮件方案

原始内容基线：`email.html`（保持不变）  
新增产物：`email-illustrated.html`

## 01 运行期数据搬移选择

- 插入位置：本期判断之后、第一个专题之前。
- 核心意思：系统不再默认搬运数据，而是在按需取数、传输、重算和就地计算之间做运行期选择。
- 隐喻：Qiliang 扳动一台低技术感的铁路道岔，带宽/时延表盘决定 KV 数据块进入哪条路径。
- 学习价值：读者一眼理解“网络并非唯一方案，传输必须与规避传输的基线同测”。
- 短标注：`按需取数`、`传输`、`重算`、`就地算`、`带宽 / 时延`。

## 02 压缩代码 Agent 探索前缀

- 插入位置：Agent 语义加速专题标题之前。
- 核心意思：结构化索引或专用检索器能把 Agent 从反复遍历仓库，改为直接命中少量候选文件。
- 隐喻：Qiliang 操作一个怪诞的“索引取件井”，从代码迷宫深处只捞出少量正确文件。
- 学习价值：读者一眼理解收益来自减少探索轮次和 token，而不仅是模型回答更快。
- 短标注：`反复探索`、`结构索引`、`候选文件`、`少走弯路`。

## 03 HBF 补出新的存储层级

- 插入位置：存储介质与器件专题标题之前。
- 核心意思：HBF 试图在昂贵高速的 HBM 和大容量低速的 SSD 之间补一层容量/带宽折中。
- 隐喻：Qiliang 搭一架中层抽屉，把上层少量高速热数据与下层大量冷数据接起来。
- 学习价值：读者先理解 HBF 的系统位置，同时看到“目前只有规格、仍待真实负载验证”的边界。
- 短标注：`HBM`、`HBF`、`SSD`、`更大容量`、`仍待实测`。

## 排版约束

- 三张图均使用 16:9，邮件内全宽显示。
- 每张图附一行不超过两句的图注，说明“读图结论”，不重复原卡片全文。
- 插画与正文使用浅灰边界隔开，不进入双栏详细卡，移动端宽度自适应。
- 不改变原邮件的标题、判断、专题条目、热点雷达、链接和文案。
