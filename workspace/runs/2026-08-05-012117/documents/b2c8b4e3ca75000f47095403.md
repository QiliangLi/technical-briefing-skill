Prompt-Induced Waste in Large Reasoning Models:
A Preregistered Two-Harness Benchmark of Coding Agents

PointFive
sarel.weinberger@pointfive.co

amir@pointfive.co

Abstract
Large reasoning models deployed as coding agents bill for deliberation (“reasoning tokens”),
tool calls, and agent turns — yet the effect of user-prompt wording on this spend has not been
measured under controlled conditions. We present a preregistered benchmark that isolates the
causal effect of prompt formulation on agent waste across six large reasoning models (DeepSeek-
V4-Pro, Kimi-K2.6, Kimi-K2.7-Code, Nemotron-3-Ultra, Inkling, GLM-5.2) served by a single
provider, operated by two real agent harnesses (PI.DEV and Claude Code through a protocol-
translation gateway), on 24 deterministic coding tasks with hidden evaluators. Across 4,643
valid runs (∼$166 of billed compute) spanning a pilot, a complete 1,728-run screening matrix, a
stress family, a frozen 8-task holdout confirmation, a post-registration replication on Kimi-K3,
and a post-registration cross-provider study on claude-sonnet-5 via the first-party Anthropic
API, we find: (1) the instruction todevelop several approaches and compare before choosing
is the most wasteful phrase tested, multiplying reasoning tokens 2.4–7.4 × on every model at
zero correctness gain, holdout-confirmed; (2) deep-thinking incantations replicate as pure waste
(1.6–2.2×) across three datasets; (3) a bounded-efficiency template (explicit scope, acceptance
criteria, stop condition) is free on all models and halves reasoning on one; (4) the harness
dominates the prompt: identical model–task–prompt triples cost 5–30 × more per success under
Claude Code than under PI.DEV at equal success rates, driven by a 12–15 × static prefix re-sent
over 2–7× more turns; (5) misleading architectural hints are the costliest input defect (2.61 ×),
while irrelevant prose is nearly free (1.03 ×); and (6) provider-side prompt caching rebates ∼61%
of billing without changing any behavioral metric, and must never be read as efficiency. A small
replication on the newly released Kimi-K3 crossed our preregistered material-difference threshold
insensitivity— its deliberation floor is ∼6× lower, so thinking cues multiply reasoning ∼15×
— while preserving every effect direction. Finally, a reversal study on a frontier closed model
(claude-sonnet-5, both harnesses on the first-party Anthropic API, Claude Code native) shows
the effects transfer: solution-tournament wording costs 2.5–2.7 × there too, certainty pressure
becomes the worst family under the native agentic harness (4.1 ×, 2.7× cost per success), and
deep-thinking cues are the mildest measured (1.25–1.30 ×) — adaptive thinking absorbs them.
All code, task fixtures, prompt variants, raw usage ledgers, and analysis scripts are public.
1 Introduction
Coding agents wrap large language models in an agentic loop: a system prompt, tool schemas, and
iterative tool execution. When the underlying model is areasoningmodel, every turn may consume
hidden deliberation tokens billed at output rates. Practitioners exchange prompt folklore — “think
step by step,” “consider multiple approaches,” “clean up while you’re there” — with little controlled
evidence about what such phrases cost or buy in an agentic setting.

Three properties of the agentic setting make naive measurement misleading. First, the harness
contributes a large fixed input prefix (system prompt plus tool schemas) that is re-transmitted every
turn, so prompt length is a poor proxy for cost. Second, providers apply automatic prefix caching
with per-token discounts, sobilledcost diverges frombehavioralwork. Third, reasoning-token
reporting is inconsistent across serving routes and can be silently dropped by protocol-translation
layers.
We therefore built a benchmark that (a) preregisters hypotheses, thresholds, and analysis
before data collection; (b) holds everything constant within paired blocks except the user prompt;
(c) separates behavioral efficiency (reasoning tokens, tool calls, turns, time) from billing efficiency
(cached vs. uncached input, actual vs. no-cache cost); (d) evaluates success with hidden deterministic
tests that never enter the agent’s workspace; and (e) runs every condition under two real harnesses
to expose harness–prompt interactions.
Contributions.(1) A reusable open benchmark: 24 deterministic multi-language coding tasks
with hidden evaluators, 18 frozen prompt variants, a resumable budget-capped runner for two
harnesses, and a dual-side capture gateway that preserves provider-reported reasoning and cache
metadata. (2) Holdout-confirmed causal findings on which prompt formulations waste reasoning-
model compute, per model and per harness. (3) A measured account of harness overhead, gateway
metadata loss, and provider cache behavior that would otherwise confound any prompt study. (4) A
preregistered replication protocol demonstrated on a newly released model (Kimi-K3) within days
of its availability.
2 Benchmark Design
2.1 Preregistration
Hypotheses (H1–H8, H12–H17), metric definitions, waste-classification rules, and experiment proto-
cols were frozen in the repository before any benchmark result was inspected. The holdout phase
additionally froze per-model variant selections, prompts, evaluators, and analysis code before any
holdout run. The Kimi-K3 replication froze its task rule, matrix, and material-difference thresholds
in a commit that predates its first result.
2.2 Models, harnesses, and serving
Six reasoning models ( ≥500B-class) served by Together AI were frozen before data collection:
DeepSeek-V4-Pro, Kimi-K2.6, Kimi-K2.7-Code, Nemotron-3-Ultra-550B-A55B, Inkling, and GLM-
5.2. Two harnesses operate them: PI.DEV 0.82.1 speaking OpenAI chat completions directly, and
Claude Code 2.1.220 speaking the Anthropic Messages protocol through a pinned LiteLLM 1.93.0
gateway that translates to chat completions. Two logging reverse proxies capture both sides of the
gateway with secrets redacted, so every run retains the provider’s raw usage object.
2.3 Tasks
24 deterministic coding tasks (8 low / 8 medium / 8 high complexity; 9 Python, 9 JavaScript, 6 Go),
each with a clean fixture, one concrete objective, explicit acceptance criteria, visible tests,hidden
deterministic tests that never exist in the workspace during a run, allowed/forbidden paths, and a
per-task evaluator. 16 tasks form the development split; 8 were frozen as holdout. Every fixture
was verified to fail its visible tests before the fix.

2.4 Prompt variants
A generator renders 18 variants per task from frozen templates. Nineprimaryvariants preserve
the objective, acceptance criteria, and test command verbatim (validated automatically): a precise
baseline; verbose repetition; deep thinking; exhaustive exploration; multiple approaches;
max certainty; adjacent cleanup; no questions autonomy; bounded efficiency (scope + smallest-
sufficient-change + stop condition); plus goal only and scoped authorization for the harness
axes. Sevenstressvariants intentionally break semantic equivalence (ambiguity, conflicting con-
straints, irrelevant context, misleading hints, multi-turn splitting and restatement) and are analyzed
separately.
2.5 Metrics
Behavioral: reasoning tokens (provider-reported, completion tokens details.reasoning tokens),
visible output tokens, tool calls by type, turns, files inspected, duplicate reads, repeated searches,
repeated test runs, time to first edit, wall time, out-of-scope changes (git diff vs. allowed paths), and
success on visible plus hidden tests. Billing: uncached and cached input tokens, logical input (=
uncached + cached), actual cost at pinned catalog prices, and estimated no-cache cost. The primary
outcome is thepaired reasoning ratio: a run’s reasoning tokens divided by the median baseline
reasoning of the same model–harness–task block. Task-clustered bootstrap yields 95% intervals. A
variant is classifiedwastefulonly when the median ratio exceeds 1.5 with CI lower bound above 1.1,
no material success gain, and the effect appears on multiple tasks.
3 Calibration: Harness Overhead and Metadata Integrity
Fixed prefix.For a trivial prompt, PI.DEV transmits 1,147–1,642 tokens of prefix (system prompt
plus 4 tool schemas), depending only on tokenizer; Claude Code transmits 15,983–20,330 tokens
(≈6.7 KB system prompt plus 24 tool schemas) —12–15 × larger on every tokenizer. The user
prompt is under 5% of logical input under PI.DEV and under 1% under Claude Code: prompt
lengthis economically irrelevant; promptcontentis not.
Gateway compatibility is empirical, not declarative.Three gateway routes were attempted.
A Responses-API route passed only 3/6 models: GLM-5.2, DeepSeek-V4-Pro, and Inkling returned
empty continuationsafter tool results when reasoning items were not replayed — a protocol-
translation failure indistinguishable from model failure without wire capture. A chat-completions
route with default settings passed 0/6: the gateway silently dropped all 24 tool schemas because
function-calling support was not declared per model. The final route (function calling declared,
parameter dropping disabled) passed 6/6 on a 14-capability suite including multi-step tool loops.
Lesson: a text response proves nothing; only an executed multi-step tool loop validates a gateway.
Metadata loss (H16).Upstream, all models report explicit reasoning-token and cached-token
fields. The gateway preserves input/output totals exactly butdropsreasoning detail and re-derives
cache fields; the Claude Code-side cost report uses the harness’s own price table for aliased models
and was measured at 3.5×the true cost. All analysis therefore uses the provider-side capture.

4 Results
4.1 Holdout-confirmed prompt effects
Per model, the three most waste-inducing variants were selected on development data only, frozen,
and re-run on the 8 unseen holdout tasks (5 repetitions, n=40 per cell, PI.DEV). Table 1 reports
median paired reasoning ratios.
Four findings survive the frozen holdout.(1)The multiple approaches instruction is confirmed
wasteful onall sixmodels (2.4–7.4 ×) — notably, it was absent from the pilot and surfaced only in
screening, illustrating the value of the wider matrix.(2) deep thinking is confirmed on every model
where selected (1.6–2.2 ×), its third consecutive replication (pilot, screening, holdout) across three
collection days; it roughly doubles wall time with identical tool behavior.(3) adjacent cleanup is
confirmed on Inkling and GLM-5.2 and, together with autonomy language, is one of only two features
that produce out-of-scope edits (5–8% of their runs; ≈0% elsewhere).(4) bounded efficiency
is confirmed neutral-or-better on all six models andhalvesGLM-5.2’s reasoning (0.48 ×) at equal
success. One selected feature failed to replicate: the autonomy phrase showed no reasoning effect on
holdout (1.00×); its real, replicated effect is scope violations. Verbose repetition of requirements
was≈1.0×everywhere: pure redundancy is free, because the fixed prefix dwarfs it.
4.2 Stress family: input defects
Against same-task screening baselines (median across models):misleading architectural hintsare
the costliest defect tested (2.61 × reasoning — models diligently chase the red herring);ambiguous
scopeproduces the worst success rate in the benchmark (83%) plus 1.44 × reasoning; splitting one
task across two turns costs ≈1.31× and restating the full task each turn ≈1.38×;irrelevant context
(1.03×) andconflicting constraints(1.05 ×) are nearly free — models filter noise well but obey
plausible misdirection.
4.3 Harness comparison
On matched model–task–prompt cells, both harnesses solved the pilot tasks at ≈100%, but Claude
Code cost5–30 × more per success(e.g., Nemotron:$0.32 vs.$0.018), driven multiplicatively
by the 12–15× prefix and 2–7× more turns (10–41 vs. 5–7). Harness–model interaction is strong:
Kimi-K2.7-Code stays at ∼10 turns under Claude Code while GLM-5.2, Kimi-K2.6, and Nemotron
thrash toward the turn ceiling on tasks they solve in ≤7 turns under PI.DEV. Prompt effects do
not transfer across harnesses (H12): goal-only promptsreducereasoning under Claude Code (whose

4.4 Cache behavior
Provider-side prefix caching is automatic, free to populate, and rebated ∼61% of the would-be bill
($390 estimated no-cache vs.$153 actual) while leaving every behavioral metric unchanged — the
purest possible demonstration that cache savings must never be reported as efficiency. Hits are
probabilistic (full/partial/none alternate under identical conditions), the cache is shared across
sessions (fresh Claude Code sessions routinely receive first-turn hits of ∼90% of the 16–20k prefix),
60-second delays showed no eviction, changing the working directory breaks reuse (the harness
embeds it in the system prompt), and one model–route pair (Nemotron via PI.DEV) receivedzero
cached tokens across every phase — a provider-side anomaly that persisted for three days and would
silently distort any cost-based comparison that ignored it.
5 Post-Registration Replication: Kimi-K3
Within a day of Kimi-K3’s appearance on the provider (2.8T-parameter MoE per its announcement;
1M context;$3/$15 per M tokens), we froze a replication protocol — six pilot tasks, four variants
(baseline, multiple approaches, deep thinking, bounded efficiency), 72 PI.DEV runs plus a
24-run Claude Code directional arm, and material-difference thresholds (reasoning ratio differing
>30% frombothKimi-K2 comparators, classification flips, >5pp scope-compliant-success change) —
before viewing any result.
The PI.DEV arm completed 72/72 at 100% success ($0.82 actual; the model’s cache rebate was
81%). The thresholdwascrossed, in an instructive direction: Kimi-K3’s baseline deliberation floor
is ∼6× lower (median 55 reasoning tokens vs. 351/195), so multiple approaches reaches16.6 ×
[10.7, 34.1] and deep thinking 14.8× [4.1, 33.9] against its own baseline — yetabsolutewaste
tokens remain at or below K2-generation levels (625 vs. 1,606 median under multiple approaches)
and cost per compliant success is the lowest of the three generations at baseline ($0.0062) despite
2.5–3.3× unit prices. bounded efficiency confirmed neutral (0.89×, CI entirely below 1). Every
effect direction and classification was preserved; no new compatibility, metadata, or cache behavior
appeared. The practical reading: on a frugal-by-default reasoner, prompt wording becomes the
dominantlever on deliberation spend — a single thinking-cue sentence multiplies it∼15×.
6 Post-Registration Cross-Provider Study: Claude Sonnet 5
The main benchmark ran open-weight models on one provider, with Claude Code reaching them
through a translation gateway. To test whether the effects are artifacts of that stack, we reversed
it: both harnesses against thefirst-party Anthropic API( claude-sonnet-5), with Claude Code in
its native environment — no gateway, no aliasing, its own prompt-caching path. The protocol (9
variants, the 6 pilot tasks, 2 repetitions; 108 PI.DEV runs plus a 54-run native-Claude Code arm)
was frozen before any result existed. All 162 runs were valid ($8.81 billed,$34.31 no-cache).

schema taxonomy. The frozen primary metric is therefore the pairedtotal-output-tokenratio

Results.The effects transfer. multiple approaches is again the reliable offender on both
harnesses (2.70× [2.14, 3.86] under PI.DEV, 2.52 × [1.73, 3.48] under native Claude Code) — inside
the open-model range (2.1–4.0 ×) on the same tasks and metric. The neutral set replicates exactly:
verbose repetition ≈1×, autonomy language ≈1×, bounded-efficiency framing free (0.93–1.02 ×).
The harness economics persist on the frontier stack: native-Claude Code baseline cost per compliant
success is ∼15× PI.DEV’s ($0.41 vs.$0.027 no-cache). Two divergences are instructive. First,
max certainty — mostly a DeepSeek quirk on open models (1.85 ×) — is theworstfamily measured
on Sonnet 5 under native Claude Code: 4.13 × output tokens [1.42, 8.57] and 2.7 × no-cache cost
per success; certainty pressure buys re-verification loops, and an agentic harness gives them room to
run. Second, deep thinking — holdout-confirmed wasteful on 5/5 open models — is the mildest
elevated effect here (1.25–1.30 ×, below every open model under PI.DEV), consistent with the
model’s adaptive-thinking controller absorbing explicit thinking incantations that fixed-effort open
reasoners obey literally. Scope compliance was perfect (162/162, including adjacent cleanup,
which widens diffs on open models), and the provider’s cache rebated 69–75% of billing (vs. ∼61%)
at identical behavioral metrics — reinforcing that rebates must never be read as efficiency.
7 Discussion
For practitioners.Five rules survived every replication stage: never request several compared
approaches unless the comparison itself is the deliverable; never add deep-thinking incantations;
keep scope-expanding and autonomy language out unless expansion is wanted (it is the only
phrasing family that widens diffs); a bounded-efficiency template is free insurance everywhere; and
judge prompts on reasoning/tool/turn metrics priced at no-cache cost, never on the cached bill.
Input hygiene matters asymmetrically: cutting fluff saves almost nothing, but removingunverified
architectural hintsandambiguitysaves a lot.
For harness and gateway builders.The harness is the largest cost decision a user makes
— larger than model choice and far larger than any prompt effect. Static-prefix size and turn
discipline dominate. Protocol translators can silently invalidate benchmarks (dropped tool schemas,
empty reasoning continuations, dropped usage detail); dual-side wire capture should be considered
mandatory instrumentation for any cross-provider agent evaluation.
For benchmark methodology.Preregistration caught us twice: a screening signal ( no questions autonomy
reasoning effect) that died on holdout, and a replication threshold that fired for a reason (denomi-
nator sensitivity) the ratio metric alone would have misrepresented — the absolute-token view had
to be reported alongside. Both would likely have become confident false claims in an unregistered
study.
8 Limitations
Tasks are small ( ≤4 files) and success ceilings are high under PI.DEV (92–97%), limiting power
to detect correctness effects of wasteful prompting; effects at real-repository scale are unmeasured.
One provider, one region, essentially one gateway implementation; the Claude Code holdout and
Kimi-K3 Claude Code arms are directional (budget-capped per preregistered ceilings). Collection

9 Conclusion
Prompt wording causes large, replicable, model- and harness-dependent differences in reasoning-
model agent cost at equal task quality. The cheapest interventions are subtractive: delete thinking
theater, delete solution tournaments, delete unverified hints — and state scope, criteria, and a
stop condition. Everything needed to reproduce, extend, or re-analyze this benchmark — fixtures,
hidden evaluators, prompt generators, runners, wire captures, ledgers, and analysis — is available
in the repository.
