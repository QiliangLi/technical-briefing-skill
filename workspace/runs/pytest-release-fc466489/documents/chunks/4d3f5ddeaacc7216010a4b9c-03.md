6 Related Work
LLM request scheduling.Recent work on LLM serving
has explored request scheduling from multiple perspectives,
including KV$-aware and SLO-aware scheduling, dynamic
rescheduling with request migration, and flexible request
partitioning across instances [ 42, 38, 43, 59, 11, 40]. Our
work builds upon these insights and mechanisms, and fur-
ther derives agent-session-aware hints for the scheduler to
improve serving performance for agents. Unlike systems that
co-design serving with agent applications and require appli-
cations to expose inter-request structure [26, 30], SMETRIC
operates entirely on the provider side, treating agents as un-
modified clients. This matches how LLM providers, including
BAILIAN, serve agents today.
Serving KV$ efficiently.Reusing KV$ across requests
13

## PDF Page 14

has been widely studied to avoid recomputing KV tensors
for LLM serving, and both industry and academia have built
mature system mechanisms for supporting KV$ reuse [ 15,
16, 22, 49, 50, 57, 52]. We build upon the mechanism of
KV$ reuse, including multi-level KV$ store, while providing
a systematic analysis and optimizations of the scheduling
aspects for better utilization of the multi-level KV$ store.
Other KV$-related optimizations.Besides cross-request
reuse, recent work also optimizes the memory footprint, trans-
fer cost, and placement of KV$ with a system–algorithms
co-design. For example, CacheGen compresses and streams
KV states to reduce KV$ transfer latency and bandwidth
consumption [27, 23, 18]. KV quantization and compres-
sion methods reduce KV$ memory pressure through low-bit
quantization, token pruning, layer-wise allocation or unified
compression [28, 20, 24, 10, 56]. Despite their potential per-
formance advantages for KV$ reuse, these techniques com-
promise model accuracy, which to the best of our knowledge
has limited their adoption in production serving. Neverthe-
less, these optimizations can strengthen several aspects of our
session-centric balanced design if applied. For example, with
a largely compressed KV$ size, GPU cache hits become more
important, and SMETRICcan achieve them in a load-balanced
way.
Optimizing LLM serving.Beyond cluster-level scheduling
and KV$ management, recent work has optimized LLM serv-
ing at different layers of the stack. For example, DeepSeek-
V3 and DeepSeek-V4 reduce long-context inference cost
through algorithm-architecture co-designs such as MLA and
compressed sparse attention [ 12, 13], FlashInfer [ 51] im-
proves attention execution through customizable kernels and
optimized KV layouts, BlitzScale and Aegaeon improve elas-
ticity and resource scaling for serving workloads [ 48, 55],
and many others [ 21, 51, 25, 22]. These optimizations are
orthogonal to SMETRIC.
7 Conclusion
Agentic serving shifts the goal of LLM scheduling to cluster-
wide TPS and makes KV$ reuse dominant. Our study of two
real-world traces shows that existing schedulers trade load
balance for KV$ reuse, and that this trade is unnecessary: the
global-tier KV$ store decouples reuse from request place-
ment, and the workload’s intra-session locality means balanc-
ing each session’s first request suffices to balance the cluster.
SMETRICturns these insights into balanced session-centric
scheduling—first requests scheduled for balance, follow-up
requests routed cache-aware—and outperforms state-of-the-
art schedulers: 10–16 % higher TPS under prefill-decode
colocation with a global store and 2–34 % higher prefill TPS
under disaggregation across global-tier provisionings.
