Probe筛选和重排提升复杂工具调用参数正确率

论文发现工具参数生成前的隐藏状态含有正确性信号，提出ParamBench、PBT和PGR。方法针对嵌套、条件依赖和跨调用参数，分别改进训练筛选与候选选择。

机制
线性probe预测每个参数值是否正确，PBT用可靠调用伪标签微调，PGR对多个候选按候选、字段或字段集重排。ParamBench按嵌套深度和依赖关系划分L1至L5难度。
结果
五个开放模型上，平均exact match由零样本19.7%升至普通微调51.6%，PBT再升至59.6%，probe的in-domain AUC为0.986。PBT在35个模型数据集组合均高于SeedSFT，最深两个基准中PGR额外带来4.6个EM点。
边界
数据来自云网络工具调用场景，难度等级跨领域未验证。Probe绑定模型、数据和采样温度，跨域需重训，PGR还增加候选采样成本，论文未报告工具RTT或端到端任务成功率。
启发
可用轻量probe筛选高风险参数调用或重排候选，优先覆盖嵌套和跨调用推导。接入项目工具schema前应重新校准，并测额外采样对Token、时延和成功率的影响。

PhyAI用统一运行时连接Physical AI端侧与云端推理

PhyAI把模型适配器与共享图执行、GPU kernel、内存管理和并行服务分开，让同一代码路径覆盖板载、边缘和云部署。11个测量配对均更快，speedup为1.40至4.65倍。

机制
conditioning、solver、cache和输出逻辑留在adapter，运行时统一调度和执行；控制时间Roofline把策略推理与环境执行分开，定位瓶颈。
结果
Cosmos3-Nano-Policy在8张H20（CFG=2、TP=4）上由2.46秒降至1.18秒，获2.08倍加速。GR00T N1.7在A40的匹配LIBERO-10条件下成功率91.8%（459/500），官方91.2%。
边界
专用runtime在部分配置仍更快，Cosmos3吞吐随batch仅增14.3%。评估集中于Physical AI和模拟环境。
启发
可借鉴模型逻辑与共享执行层的边界，用端到端基线和控制时间Roofline评估Agent运行时。不能只用kernel级speedup代表服务收益。

ToolLIFT用功能级工作流图解耦工具规划

ToolLIFT把具体工具轨迹提升为功能级工作流图，再分开进行流程规划和工具选择，并用源门控奖励约束参数来源。三个OOD数据集上，Llama准确率较最强基线提高3.22至4.90个百分点。

机制
FWG编码跨工具共享的流程节点与数据流，workflow planner先决定全局步骤，tool selector再选择实现；扰动训练提高工作流变化下的鲁棒性。
结果

边界
评估是离线工具规划和模拟工具集合，未报告真实Agent的tool call次数、token、端到端时延或网络开销。长链路错误累积和线上稳定性仍未验证。
启发
可用“功能级流程图加工具选择”减少对单一工具轨迹的绑定，再用真实Read、Grep、tool-call和端到端时延验收，不能只看离线准确率。

机制

GUI-MCP研究显示工具可用不等于Agent会用

OSWorld-MCP中，reasoning模型获得工具后准确率提高4.0个百分点，non-reasoning模型反而下降5.9个百分点。研究同时发现冗余截图会推高输入成本，工具选择和上下文管理需要分开评估。

机制
实验在同一harness中区分工具可用性、调用决策和上下文压缩；成功调用后删除冗余截图并缩短图像历史窗口，减少后续输入。
结果
reasoning policy只在309个任务中的55个调用工具，占tool-reachable任务23.9%。重训后的压缩Agent准确率37.8%对未压缩33.0%，输入成本为53%。
边界
dense tool bonus可把工具采用率从0.03推到0.33，但held-out准确率未同步提升。压缩收益依赖观测规则和重训，未验证代码Agent生产P95。
启发
应分别验收工具选择、调用后状态整合和上下文token成本。可借鉴删除冗余观测，但必须同观测规则重训并同时监测准确率、token与tool-call次数。

TaskPress用任务指南压缩可复用KV缓存

TaskPress以任务指南为meta-query，在prefill一次评分并压缩KV，缓存可服务同任务的多个查询。LLaMA-3.1-8B在RULER-16K中75%驱逐平均分68.4，高于KVzip 62.2。

机制
cross-attention按任务指南筛选并驱逐无关token，int4 per-token scale识别Value outlier。默认int4提供4×压缩，75%驱逐时总压缩可达16×。
结果
64K上下文单A100上，0→75%驱逐使TPOT由50.1降至32.8 ms/token，吞吐由19.9升至30.5 tokens/s。8K上下文、75%驱逐、200查询延迟48.06s（延迟优先50.24s），KV缓存236.88MB。
边界
收益依赖任务指南，任务偏离或高密度needle会误驱逐；FP16/BF16需显式计算outlier统计。未测WAN、跨域一致性或多租户。
启发
可用任务级指南构建跨查询复用的Agent Cache，测指南稳定性、复用次数、字节与剪枝成本；漂移时回退全缓存。

SAKI按注意力分数优化低秩KV检索

SAKI把低秩KV压缩目标转向attention score畸变，保护top-k检索相关性。多模型均提升召回，但证据仍限于4K上下文和recall。

机制
方法根据rank-r压缩的score畸变构造加权低秩目标，在query-key算子上做闭式非对称分解，并按head生成映射。理论margin条件控制top-k recall。
结果
LLaMA-3.1-8B的4K文本、rank32测试中，SAKI-opt top-64 recall为0.799，高于key-PCA的0.748。rank32移除PCA误差20%，76.9% heads改善，score-MSE相关性为0.997。
边界
验证集中在4K校准域和固定top-64 recall，没有端到端生成；rank≤32未达0.95。论文未测跨域字节、WAN RTT或P95。
启发
跨域KV压缩应同时看attention分数畸变和top-k命中率。可在Agent Cache的query-key对上按margin设回退，测量压缩字节、端到端P95和WAN成本。

AOS以控制面和运行面组织分布式Agent治理与协调

AOS将分布式Agent系统分为治理控制面和运行时协调面，分别管理意图授权、审计以及生命周期、路由、上下文和调度。区域部署可减少例行决策对WAN的依赖，并保留跨委派行动的治理链。

机制
能力请求先按授权、驻留、协议和信任等硬约束筛选，再按语义适配、可靠性、延迟、成本和地域排序。运行面通过适配器调用，失败时支持重试、回退、跨区域转移或人工升级；控制面可部署在单进程、服务、区域或联邦拓扑。
结果
上下文状态与权威状态分离，可靠性要求覆盖来源、溯源、新鲜度、授权和矛盾处理，冲突记录不得静默平均，并保留每次版本证据。
边界
这是参考架构提案，不是有基准的实现。论文没有WAN RTT、传输字节数、缓存命中率、P95时延或压缩比实测，区域一致性和撤销延迟仍是设计权衡，后续规范也在演进。
启发
跨域Agent Cache、工具结果和记忆共享需要明确权威状态、版本溯源、缓存安全行为和一致性边界。评估时应补测真实RTT、带宽、命中率、尾延迟与租户隔离，避免把架构目标当成性能收益。
