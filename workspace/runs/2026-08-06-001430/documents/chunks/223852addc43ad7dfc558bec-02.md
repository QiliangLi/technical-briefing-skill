ogy.The prototype currently supports only linear DAGs. Adding fan-in
and fan-out would broaden the range of supported stream-processing applications.
Distributed execution.While distributed deployment is already possible
through manual configuration, future work includes automatic stage placement,
transparent transport selection, and host-aware autoscaling.
Dynamic workflow adaptation.The execution graph is currently static.
Supporting runtime DAG transformations (e.g., stage fusion and scission) and
policy- or LLM-driven sub-workflow creation would enable adaptive execution
while preserving application semantics.
7 Conclusions
We presented Epico, a serverless stream-processing runtime in which pipelines are
long-lived WebAssembly components, scaled independently per stage from zero
against queue-depth SLOs, and connected through direct broker-free ZeroMQ
channels. We showed that AOT reduces cold-start latency from tens or hundreds
of milliseconds to sub-millisecond, and that a credit-based sliding-window proto-
col between workers and dispatchers raises per-worker throughput by up to4.2×
relative to a strict request–reply baseline. Compared head-to-head with Apache
