Abstract

model’s fixed context window. Existing compaction meth-

Introduction
In recent years, the paradigm of Large Language Models
(LLMs) (Masterman et al. 2024) has transitioned from pas-
sive text generation (Li et al. 2024) to active, autonomous
agency. By embedding an LLM within an interactive exe-
cution loop, modern AI agents (Durante et al. 2024) can
perceive environments, reason over objectives, and execute
actions via external tools, APIs, or bash shells. At each dis-
crete time stept, the agent reads the cumulative historical
transcript of the trajectory, synthesizes an internal mono-
logue,andemitsastructuredaction.Theunderlyingruntime
environment executes this action and appends the resulting
observation back into the transcript, preparing the agent for
the subsequent turn. Because contemporary autoregressive

However,thisarchitectureintroducesasevereengineering

et al. 2025). Every LLM is bounded by a strict maximum
sequence length that it can process at once. Because the
agentic trajectory at any given turn is a literal concatenation
ofallpriorprompts,tooloutputs,andenvironmentresponses,
the transcript grows continuously and without bound as the
agent keeps acting.
Once the cumulative transcript outgrows this maximum
capacity, the system encounters an unrecoverable failure
state: the LLM can no longer process the next step, effec-
tively paralyzing the agent. For long-horizon planning (Er-
dogan et al. 2025), complex software engineering tasks, or
open-ended web browsing, hitting this context wall is not
a matter of if, but when rendering even modern ultra-large
context windows insufficient.
Topreventthiscatastrophicoverflow,contemporaryagent
frameworks rely on compaction or compression (Ichikawa
et al. 2026): a suite of lossy transformation techniques de-
signed to compress an over-long transcript into a truncated
form that fits comfortably within context-window length.
The current state-of-the-art methods generally fall into four
paradigms:
•NaiveTruncation(Wangetal.2026):Droppingtheold-
estNturns entirely, assuming older context is irrelevant.
•Hierarchical Summarization(Kang et al. 2026): Peri-
odically prompting the LLM to condense historical turns
into high-level textual summaries.
•State Folding(Fu et al. 2026): Mapping conversational
historiesintoexplicit,structuredJSONorkey-valuestate
objects.
•Retrieval-Augmented Generation (RAG)(Park et al.
2023): Offloading historical context into an external vec-
tor database and retrieving relevant chunks via semantic
similarity.

Related Works
Prior compaction methods differ in what they remove, when
removalhappens,andwhetherdiscardedcontentcanlaterbe
recovered. We organize them by this last property, since it
determineswhethercompactionissafe:whethertask-critical
information can survive the process.
Full-Context(NoCompaction).Someagentsystemssim-
ply append every turn to the transcript indefinitely, as in Re-
Act and Reflexion (Yao et al. 2023; Shinn et al. 2023). This
preserves perfect fidelity while context remains available,
but it is not a true compaction strategy: once|T|> L, the
method fails.
SlidingWindow.Acommonbaselinekeepsonlythemost
recentNturns and drops older ones (Ding et al. 2026). This
issimpleandbudget-compliant,butonceavaluefallsoutside
the window, it is lost permanently.
LLM Summary.Another approach replaces older turns
with a natural-language summary produced by the model
(Packeretal.2023).Thisretainsmoresemanticcontentthan
truncation,butremainslossy:omittedorparaphraseddetails
cannotberecovered,andeachcompactioneventincursextra
latency and cost.
Structured State.Instead of free text, prior work may
compress history into a fixed-schema state object such as
JSON (Fu et al. 2026). Schemas can preserve anticipated
fields more reliably than open-ended summaries, but any
unmodeled information is still discarded irreversibly.
RAG Memory.Retrieval-based methods store past obser-
vationsexternallyandre-injectretrievedchunksintocontext
when needed (Lewis et al. 2020). Although the store may
retain everything, recall is only implicit: the agent cannot
request a specific prior item directly, and recovery depends
on retrieval quality.
Summary.Across these approaches, the key limitation is
the absence of reliable, addressable recall. Some methods
discard information outright; others preserve it only indi-
rectly through summaries, schemas, or similarity-based re-
trieval. ARC addresses this gap by storing observations ver-
batim under canonical identifiers and replacing them in the
livetranscriptwithshortcitations,allowingexplicitrecovery
of exact prior content on demand.

Proposed Method
Design Principle
Every baseline in the Related Works Section conflates two
decisions that need not be coupled: (1) what to keep, and
(2) what to show the model right now. ARC separates them.
It keepseverything, always, in a content-addressed store; it
decides what to show using the same length-bounded logic
as the other baselines, but every omission leaves behind an
explicit,dereferenceablepointer.Recoveryisthenadecision
that the agent makes, not a probability that the retriever gets
right.

System-Level Guarantee
TheguaranteeweestablishforARCisapropertyofthemem-
ory mechanism, not of the agent that uses it. It ensures that
anystoredobservationremainsexactlyrecoverablethrougha
validaddress,butitdoesnotensurethatthelanguagemodel

the content is retrieved. We therefore draw a deliberate dis-
tinction between address-conditioned recoverability, which
themechanismprovides,andend-to-endtasksuccess,which
the agent must additionally achieve. In the same spirit, we
use persistent addressability to mean that every issued ad-
dress remains valid in the external catalog for the lifetime
of the task. This is a weaker and more realistic requirement
thankeepingallcitationssimultaneouslyvisibleintheactive
prompt, which, as we show in the appendix, is incompatible
with a turn-independent context bound.
