Same Task, Different Work:
Prompt-Induced Waste in Coding Agents
A Preregistered Study of Reasoning, Tools, and Harnesses

PointFive
sarel.weinberger@pointfive.co

Abstract
Two prompts can request the same code change and produce the same correct patch, yet
cause a coding agent to perform radically different amounts of work. We test this effect in
a preregistered benchmark spanning 4,644 valid runs, 24 deterministic tasks, six open-weight
reasoning models, a post-registration Kimi-K3 replication, a first-party claude-sonnet-5 study, and
two real agent harnesses. Asking an agent to develop and compare several approaches multiplies
reasoning by 2.4–7.4 × across the frozen holdout without improving success. The instruction
does not produce broader implementation: in 2,801 condition-blind annotated traces, it creates
roughly three elaborated but discarded solution branches and exactly one implemented approach.
Certainty language produces a different failure mode. It propagates into repeated tests, additional
turns, latency, and context growth; runs with the highest observed redundant-verification level
cost 18× the clean-run median, execute 2.5 × the tool calls, and take 3 × the wall-clock, with no
success gradient. These mechanisms therefore have different cost carriers: branch tournaments
are primarily token-borne, whereas verification loops are tool-borne. Harness design amplifies
both: in our matched setting, Claude Code carries a 12–15 × larger static prefix, uses 2–7 ×
more turns, and costs 5–30 × more per success than PI.DEV. The main effects survive a frozen
holdout, paraphrase tests, Kimi-K3, and a first-party Sonnet 5 study. A bounded-efficiency
instruction preserves diagnosis and validation while avoiding the measured waste mechanisms.
Prompt engineering for coding agents is therefore not merely wording optimization: it is the
design of what work the agent is asked to perform, how that work propagates through tools, and
when it should stop.
1 Introduction: the same task can imply different work
A coding prompt does more than describe an objective. It also tells the agent what work to perform
on the way there. Consider two instructions attached to the same small bug fix. One asks the agent
to develop several distinct approaches, compare their trade-offs, and only then choose the best. The
other asks it to inspect only what the evidence requires, make the smallest sufficient change, run
the relevant tests, and stop. Both can produce the same correct patch. They do not produce the
same computation. The first instruction launches a tournament of candidate solutions; the second
directs the agent toward a bounded execution path.
This distinction is easy to miss when prompt efficiency is treated as a text-compression problem.
In an agent, the user’s words sit inside a much larger system: a fixed harness prefix, tool schemas,
repeated model turns, tool outputs that re-enter context, and provider caching. A short sentence

We ask three questions. First, how much additional work can prompt wording create when
the task, model, harness, and success criterion are held fixed? Second, what kind of work is
created—discarded reasoning branches, re-verification, repository exploration, or tool use? Third,
when does that work remain inside model deliberation, and when does it propagate into test runs,
additional turns, latency, and end-to-end cost?
We answer these questions with a preregistered paired benchmark of 24 coding tasks with
hidden deterministic evaluators. The original study uses six open-weight reasoning models and two
harnesses, PI.DEV and Claude Code; post-registration studies add Kimi-K3 and first-party claude-
sonnet-5. The full corpus contains 4,644 valid runs, and 2,801 provider-exposed reasoning traces
receive condition-blind, evidence-quoted semantic annotation. The technical design, exact prompts,
full matrices, instrumentation checks, and robustness analyses are reported in the appendices. The
main text follows the argument rather than the collection chronology.
The evidence supports three claims.Prompt wording allocates agent work: requesting
compared approaches or repeated certainty creates large cost increases without a measured success
gain, whereas a length-matched restatement does not.Waste has structure: solution tournaments
produce token-borne discarded branches, while certainty pressure produces tool-borne verification
loops.The harness amplifies the prompt: prefix size, turn discipline, and tool policy determine
how often the consequences of an instruction are replayed.
2 Prompt wording allocates agent work
The primary conditions preserve the task objective, acceptance criteria, and test command; only
the added instruction changes. The strongest result is not that longer prompts cost more. They
generally do not. It is that phrases which request additional work reliably cause the agent to perform
that work, even when the benchmark rewards only the final correct patch.
On the frozen eight-task holdout, multiple approaches is classified wasteful on every one of
the six original models, increasing reasoning by 2.4–7.4 × with no material success improvement.
deep thinking increases reasoning by 1.6–2.2 × on every model for which it was selected. By

The negative controls matter. A bounded-efficiency instruction—begin with the failing test and
likely implementation files, inspect more only when evidence requires it, make the smallest sufficient
change, run the relevant tests, and stop when the acceptance criteria pass—is neutral or better on
all six holdout models. It does not reduce observed diagnosis, evidence collection, or final validation.
Its role is not to make the model terse at any cost; it declines to authorize work that the task does
not require.
The stress family sharpens the same distinction. Irrelevant context and conflicting constraints
are nearly free in this benchmark, but a plausible wrong architectural hint raises reasoning 2.61 ×,
and ambiguous scope produces both the lowest success rate (83%) and 1.44 × reasoning. The models
filter generic noise better than they resist plausible misdirection. Detailed stress results appear in
Appendix C.
3 Waste has structure
The aggregate token ratios tell us that work increased, but not what the agent did with it. The
annotated traces and deterministic tool telemetry show that the two dominant mechanisms are
qualitatively different.
3.1 Branch tournaments: expensive ideas that never reach the repository
The multiple approaches instruction does exactly what it says. Relative to baseline, the model
considers 3.5 additional approaches on average, elaborates about three that are never used, and
implements exactly one. The frozen holdout reproduces the same +3 .5/ + 3.0/ + 1.0 pattern. The
instruction therefore does not buy a second implementation or an experimental comparison; it buys
an internal tournament whose losing branches are discarded before they reach the repository.
This mechanism is primarily token-borne. The first observed discarded branch raises median
no-cache run cost by approximately 1.9 ×, while median tool calls remain nearly flat (7 to 8). Higher
branch levels do not produce a corresponding rise in repository exploration or code edits. The agent
is not broadly testing alternative implementations; it is elaborating them in reasoning text and then
abandoning them.
3.2 Verification loops: when caution becomes action
Certainty pressure follows another path. The max certainty instruction adds re-verification of
already established facts, more reasoning devoted to checking, repeated tests, and activity after the
last edit and first fully green visible test. Every additional tool result re-enters the model context,
where it can induce another turn and another round of checking.
Figure 1 shows the contrast. Branch count changes model cost while tool activity stays nearly
flat. Redundant verification causes cost, calls, and latency to rise together. At the highest observed
verification level, runs cost 18.25 × the clean-run median, execute 15 rather than 6 median tool
calls, and take 3 × the wall-clock, with no success gradient. This is a descriptive comparison across
observed mechanism levels, not a claim that the annotation level itself was randomly assigned; the
causal result is that certainty wording increases the verification behavior and downstream work.

3.3 Misdirection: plausible hints are more dangerous than noise
The wrong-hint condition adds one unsupported assumption and one stated hypothesis while
grounded hypotheses remain unchanged. Deterministically, pre-first-edit deliberation rises 4.2 ×.
Unsupported assumptions are also the only annotated semantic marker negatively associated with
success (ρ = −0.19). This mechanism is neither a branch tournament nor a verification loop: the
model is spending work to make an unverified premise coherent.
3.4 Bounded efficiency: avoiding waste without suppressing work
Bounded efficiency is the useful null. Relative to baseline, observed error diagnosis, final validation,
and unused branches all change by 0.0; every deterministic redundancy metric also changes by 0.00,
with tests, edits, and diagnosis preserved. The instruction is effective not because it removes a
necessary reasoning stage, but because it does not trigger the additional mechanisms described
above.
Visible traces are not a complete transcript of model computation. Consequential computation
may occur without a semantically interpretable chain of thought [ 7]. We therefore make claims
about provider-exposed reasoning text and observable agent behavior, not hidden cognition. claude-
sonnet-5, whose reasoning is billed inside output but not recoverable as text, is excluded from all
trace-level claims.
4 The harness amplifies the prompt
A prompt does not determine cost alone. The harness determines the fixed context around it, how
many turns occur, which tools are exposed, and how often the consequences of an instruction are
replayed.

transmits 15,983–20,330—a 12–15 × gap. On matched model–task–prompt cells, Claude Code also
uses 2–7× more turns. Together these mechanics produce a 5–30 × difference in cost per success

6 Implications: prompt design is work design
The findings suggest four practical principles.
Ask for alternatives only when alternatives are the deliverable.A request to compare
approaches is appropriate when comparison itself is valuable. For an ordinary patch, it reliably buys
discarded deliberation. When alternatives are needed, the prompt should state whether they must
be briefly listed, deeply analyzed, implemented, or experimentally evaluated. Those are different
workloads.
Replace certainty language with an executable stop rule.“Be absolutely certain” has
no observable stopping condition and can convert caution into a verification loop. A measurable
instruction is safer: run the relevant suite after the final edit; rerun only after a relevant change or
a failure; stop when the acceptance criteria pass.
Optimize the mechanism, not only the token count.Branch tournaments are primarily
token-borne, so they require constraints on elaboration and deliverables. Verification loops are
tool-borne, so they require stopping policies and duplicate-action guards. Context compression can
reduce the price of tool outputs, but it does not by itself prevent the agent from issuing unnecessary
calls.
Measure harness behavior separately from model behavior.Static prefix, turn count, tool
composition, cache state, and protocol translation can dominate the user-prompt effect. Benchmarks
that do not capture both sides of a gateway can silently attribute harness failures or metadata loss
to the model.

8 Limitations
First, provider-exposed reasoning text is neither complete nor necessarily faithful; our semantic
claims concern observable traces, not hidden cognition. Second, the tasks are small (at most four
files) and have high success ceilings. Multiple approaches may be useful on repository-scale or
architectural work where alternatives require genuine implementation and evaluation. Third, the
prompt conditions are randomly assigned within paired blocks, but annotated mechanism levels
are observed mediators rather than randomized treatments; the 18 × verification comparison is
therefore descriptive. Fourth, exact per-turn cost attribution is not available, so tool-induced model
cost is bounded at 4–12% rather than identified exactly. Fifth, the Claude Code arms are smaller,
provider prices and cache behavior are time-specific, and the remaining new-task and long-validation
expansion arms were still in progress at writing. Full measurement limitations, judge agreement,
zero-inflated count handling, and classifier caveats appear in Appendix D.
9 Conclusion
Two prompts can produce the same correct patch while asking the agent to perform radically
different amounts and kinds of work. Requests for several approaches create internal solution
tournaments whose losing branches are paid for and discarded. Demands for certainty create
verification loops that escape into tools, turns, latency, and context growth. Harness design then
determines how strongly those consequences are amplified. Across the tested tasks, none of these
mechanisms improves success, while a bounded instruction preserves diagnosis and final validation.
Prompt engineering for coding agents should therefore be understood as work design: specify the
deliverable, constrain unnecessary paths, and define when the agent is done.

A Experimental Design and Preregistration
A.1 Preregistration
Hypotheses H1–H8 and H12–H17, metric definitions, waste-classification rules, and experiment
protocols were frozen in the public repository before any benchmark result was inspected. The
holdout phase additionally froze per-model variant selections, prompts, evaluators, and analysis code
before any holdout run. The Kimi-K3 replication froze its task rule, matrix, and material-difference
thresholds before its first result. Expansion hypotheses E1–E12, manifests, power analysis, budget
caps, and stopping rules were registered separately; expansion runs remain tagged separately and
are not merged into the original preregistered results.
A.2 Models, harnesses, and serving
The original study froze six reasoning models ( ≥500B-class) served by Together AI: DeepSeek-
V4-Pro, Kimi-K2.6, Kimi-K2.7-Code, Nemotron-3-Ultra-550B-A55B, Inkling, and GLM-5.2. Two
harnesses operated the models: PI.DEV 0.82.1 through OpenAI chat completions directly, and
Claude Code 2.1.220 through the Anthropic Messages protocol and a pinned LiteLLM 1.93.0
translation gateway. Two logging reverse proxies captured both sides of the gateway with secrets
redacted, preserving the provider’s raw usage object for every run. Kimi-K3 and claude-sonnet-5
were added only through separately frozen post-registration studies.
A.3 Tasks and evaluation
The benchmark contains 24 deterministic coding tasks: eight low, eight medium, and eight high
complexity; nine Python, nine JavaScript, and six Go. Each task has a clean fixture, one concrete

objective, explicit acceptance criteria, visible tests, hidden deterministic tests that never exist in
the workspace during a run, allowed and forbidden paths, and a per-task evaluator. Sixteen tasks
form the development split and eight were frozen as holdout. Every fixture was verified to fail its
visible tests before the agent’s fix. The small task size ( ≤ 4 files) is deliberate for causal control and
is also a limitation on production-scale generalization.
A.4 Prompt conditions
A generator renders 18 frozen variants per task. Nine primary variants preserve the objective,
acceptance criteria, and test command verbatim: baseline, verbose repetition, deep thinking,
exhaustive exploration, multiple approaches, max certainty, adjacent cleanup, no questions autonomy,
and bounded efficiency. goal only and scoped authorization define additional harness axes.
Seven stress variants intentionally break semantic equivalence through ambiguity, conflicting con-
straints, irrelevant context, misleading hints, missing criteria, or multi-turn splitting and restatement;
they are analyzed separately.
Because wording is the manipulated variable, lexical form, order, length, and position are part of
the experimental treatment. Table 2 reproduces the principal frozen clauses. Appendix F contains
all complete templates, representative rendered prompts, multi-turn boundaries, and SHA-256
checks against the run ledger.
A.5 Metrics and classification rules
Behavioral outcomes include provider-reported reasoning tokens, visible output tokens, tool calls
by type, turns, files inspected, duplicate reads, repeated searches, repeated test runs, time to first
edit, wall time, out-of-scope changes, and success on visible plus hidden tests. Billing outcomes
include uncached and cached input, logical input, actual cost at pinned catalog prices, and estimated
no-cache cost.
The original primary outcome is the paired reasoning ratio: each run’s reasoning tokens divided
by the median baseline reasoning in the same model–harness–task block. A variant is classified
wasteful only when the median ratio exceeds 1.5, the task-clustered 95% confidence interval has
a lower bound above 1.1, there is no material success gain, and the effect appears on multiple
tasks. Count outcomes use per-task paired medians, task-clustered bootstrap intervals, and sign-flip
permutation tests rather than pooled correlations alone.

poor economic proxy even though prompt content can strongly change downstream work.

B.3 Cache behavior
Provider-side prefix caching is automatic and free to populate in the original serving route. It
rebates approximately 61% of the would-be bill (billed cost approximately 39% of no-cache cost)
while leaving behavioral metrics unchanged. Hits are probabilistic: full, partial, and no hit can
alternate under identical conditions. The cache is shared across sessions; fresh Claude Code sessions
routinely receive first-turn hits covering roughly 90% of the 16–20k prefix. A 60-second delay showed
no eviction, while changing the working directory breaks reuse because the directory is embedded in
the system prompt. Nemotron through PI.DEV received zero cached tokens throughout all phases
for three days, a provider-side anomaly that would distort comparisons based only on billed cost.
The first-party claude-sonnet-5 study received cache rebates of 69–75%. Because caching changes
price without changing agent behavior, the paper keeps behavioral work, actual billed cost, and
no-cache cost conceptually separate.
B.4 Native Claude Code billing reconciliation and classifiers
The 5–30× open-model harness gap cannot be caused by Anthropic-side classifiers because those
requests were served by Together AI through the translation gateway and never entered Anthropic’s
model-serving path. The measured gap is accounted for by the larger prefix, 2–7 × more turns, and
verification-heavy tool composition.
For the 54 native Claude Code runs against claude-sonnet-5, recorded cost reconciles from visible
usage categories: uncached input, cache reads, cache writes, and output. The median discrepancy is
zero and 53/54 runs reconcile within 1%. An initial uniform 33.3% discrepancy came from comparing
standard with introductory pricing. Remaining differences imply cache-write rates whose median
and 90th percentile equal the documented five-minute write premium (1.25 × input rate), with a
small upper tail consistent with one-hour-TTL writes (2 × input rate) mixed within a run. The

reported separately; no direct tool dollar cost is fabricated.

A frozen rubric defines 14 composition counts, six waste mechanisms, and ordinal quality scores

A second frozen rubric classifies navigation, search, read, edit, test, build, lint, git, environment,

freeze the extractor; blind hand-derived labels caught one TAP pass-detection bug, which was fixed
before condition-aware analysis.
“Post-success” uses a recoverable visible-test proxy: the last edit and first fully green visible
test. The moment at which hidden evaluators would have passed during a run is not observable.
PI.DEV also lacks per-call timing, and local CPU, GPU, and memory telemetry were not recorded.
D.4 Distributional and causal limits
Tool counts are zero-inflated and heavy-tailed: 94% of runs have zero post-green repeat tests, with a
maximum of six. H-T1 and H-T4 tool-layer effects are directional rather than paper-robust. Prompt
variants are assigned within paired experimental blocks, but semantic mechanism levels are observed
after treatment; mechanism-level cost curves therefore do not identify randomized mediator effects.
Cost uses pinned catalog prices at collection time. Provider-side safety classifiers may contribute
latency, but server-side classification, queueing, and generation time cannot be separated from
exposed usage fields; absence of unexplained billing is not evidence that no classifier runs.

E Post-Registration Replications and Expansion
E.1 Kimi-K3 replication
Within a day of Kimi-K3 appearing on the provider, the authors froze a protocol covering six
pilot tasks, four variants (baseline, multiple approaches, deep thinking, bounded efficiency),
72 PI.DEV runs, and a 24-run Claude Code directional arm. Material difference was defined
before results as a reasoning ratio differing by more than 30% from both Kimi-K2 comparators, a
classification flip, or more than five percentage points of scope-compliant-success change.
The PI.DEV arm completed 72/72 at 100% success, with an 81% cache rebate. Kimi-K3’s
baseline median is 55 reasoning tokens versus 351 and 195 for the K2 comparators. Multiple
approaches reaches 16.6× [10.7, 34.1] and deep thinking 14.8 × [4.1, 33.9] against that low baseline.
Absolute multiple- approaches reasoning remains at or below K2-generation levels (625 versus 1,606
median), and baseline cost per compliant success is the lowest of the three generations despite
2.5–3.3× unit prices. Bounded efficiency is 0.89 × with its confidence interval below 1. Effect
directions and classifications are preserved.
E.2 First-party claude-sonnet-5 study
The first-party study reverses the original stack: both harnesses call the Anthropic API, and Claude
Code runs natively without gateway translation or model aliasing. The frozen protocol contains
nine variants, six pilot tasks, and two repetitions: 108 PI.DEV runs and 54 native-Claude Code
runs. All 162 are valid.
The Anthropic API includes thinking in output tokens without reporting it separately. The
preregistered primary metric is therefore total-output-token ratio, defined consistently on the open-
model side. Multiple approaches is 2.70 × [2.14, 3.86] under PI.DEV and 2.52 × [1.73, 3.48] under
native Claude Code. Verbose repetition, autonomy, and bounded efficiency remain approximately
neutral (0.93–1.02× for bounded efficiency). Native-Claude Code baseline no-cache cost per compliant
success is approximately 15 × PI.DEV’s. Maximum certainty reaches 4.13 × output [1.42, 8.57] and
2.7×no-cache cost per success. Deep thinking is 1.25–1.30×. Scope compliance is 162/162.
E.3 Registered expansion
The expansion targets four evidence gaps: (a) paraphrase generalization through 25 frozen arms
including four forms per condition, length-matched controls, and instruction-position variants; (b)
repetition stability; (c) 24 new tasks including a long-validation family and a second frozen 16-task
holdout; and (d) per-model precision. Planned scale is approximately 5,600 new valid runs and
approximately 10,250 total. Failed replications are committed to prominent reporting.
At writing, the paraphrase and stability arms contain 2,105 valid runs of 2,106: three models
× six tasks × 25 arms × three new repetitions, and two models × 16 tasks × nine variants
× three new repetitions. The registered stability analysis reports within-cell no-cache cost CV
over five-repetition cells. All four paraphrase forms of multiple approaches, deep thinking, and
maximum certainty elevate reasoning on every model tested (12/12 condition–model cells, four
of four forms). Length-matched controls are 0.96–1.05 ×. All five bounded- efficiency forms are
0.85–0.93×. Multiple-approaches magnitude ranges from 3.0 × for the concise form to 6.7 × for the
verbose form; start versus end placement shifts an example effect from 5.2 × to 4.3×. Within-cell
no-cache cost CV is 12–23%, and success is unanimous in 81–97% of cells. No effect-direction reversal
is observed for a confirmed waste condition; reversal rate 0.33 appears only for verbose repetition
