INC-MoE：把专家并行的集合通信卸载进网内计算交换机

论文/来源：INC-MoE: Overlapping In-Network Collectives and Expert Computation for Expert-Parallel Mixture-of-Experts Inference

专家并行MoE服务里，dispatch与combine两次集合通信在跨节点时主导整层延迟。INC-MoE把这两次通信卸载到网内计算交换机，并与专家计算重叠，TTFT降低20.2%–33.1%。

怎么做的

具体做法：AllGather与ReduceScatter改在交换机侧执行，可并发占用链路的双向带宽；持久kernel按band重叠通信与专家计算。相对vLLM默认路径，每加速器prefill吞吐提升25.3%–49.5%，并发AG与RS等效带宽提升25.6%–31.8%，逐层输出余弦相似度保持1.0。

需要注意

评估范围要清楚：交换机由加速器仿真而非硬件实现，只评估了OLMoE-1B-7B的prefill，N=8的增益是分析值。评估MoE服务通信优化时，可以把交换机侧双向复用与端侧ring方案放在一起对比。

ThunderEP：消费级GPU的MoE通信改走单步DMA

论文/来源：Efficient Expert-Parallel Communication on PCIe-Connected Consumer GPUs

PCIe消费级GPU之间没有P2P互访，MoE专家并行通信只能经CPU内存走NCCL环形路径。ThunderEP改为单步DMA通信：单步All-Gather把6卡流量减少40%，Reduce-Scatter缩短依赖链，DMA引擎搬移数据、按发送方同步，prefill可与计算重叠。

关键结果

在6卡RTX 4090/5090与三个MoE模型上，较vLLM基线prefill最高加速1.66倍、decode吞吐最高提升1.26倍。范围限于单节点PCIe消费级GPU的MoE激活通信，不涉及KVCache与多节点，decode也无通信重叠。

异构GPU流水线的精确完成时间界：异步时延只进常数项

论文/来源：Exact Makespan Bounds and the GPipe Homogeneity Bias for Heterogeneous LLM Inference Pipelines

Callosal：用解耦内存和可编程交换机重建集群级页缓存

论文/来源：Callosal: Rethinking the Kernel Page Cache for Disaggregated Storage and Memory

分布式文件系统弱一致、缓存也难跨节点共享。Callosal把Linux页缓存重构成以共享解耦内存为中心的集群级缓存：每节点保留标准页缓存抽象，跨节点用页粒度MSI失效协议同步文件数据，由RDMA与可编程交换机承担一致性，没有中心协调节点，在近本地性能下提供强一致。

怎么做的

关键在交换机内的一致性目录：它对并发失效做线速排序并定向发送，这正是无中心协调还能保持强一致的地方。

关键结果

数字都带条件：10–30%写、争用不极端的混合读写下，平均吞吐为NFS的4.6倍；键值存储99%读、均匀访问、跨4节点约4.5 Mops，是单节点的1.72倍。但冲突写与私有覆写吞吐低于NFS，5%写时所有权迁移使系统扩展不出单节点，时延与CPU数据在可见证据中缺失。做解耦存储与内存设计时，可评估共享文件负载能否受益于交换机内一致性目录。

论文/来源：The Physical Cost of Context: Quality-Constrained Resource Accounting for Coding Agents
为什么会这样

评上下文策略时习惯看逻辑token省了多少，但缓存运行时只预填未命中的前缀：一旦策略改写了历史，可复用前缀变短，token数更少的提示实际执行成本反而更高。这是论文最反直觉也最值得记住的结论。

怎么做的

核算协议的做法：把执行预填分解为逻辑提示减去可复用前缀，同时测调用数、KV时间面积、wall time与扣除空闲的能耗；策略先过质量门，才有资格进入成本比较。论文在固定栈上对比了四种策略。

关键结果

STRATUM：把仓库认知存成知识图，供下个会话继承

论文/来源：Stratum: Repository Memory for Coding Agents Beyond the Context Window

编码Agent每个会话都在从零重建对仓库的理解。STRATUM在开发机仓库旁驻留分层知识图记忆，任务后写回笔记供下个会话继承。初步实验里，继承记忆的新会话根因文件命中21/24，纯检索只有6/24。

怎么做的

结构分冷热两层：冷层是SQLite知识图加嵌入索引，热层是RAM缓存，控制器做图感知预取与预算跟踪；Agent通过带分页与预算提示的MCP工具读写。

关键结果

成本变化更实际：8个真实bug上，继承记忆的新会话中位9次工具调用、每次调用中位输入43.3K token，纯检索是18次与196.6K，约降为四点五分之一。论文自述为草图与初步证据：原型只实现9个工具中的4个、用词法检索，判据止于文件级且未测端到端时延。落地时把根因与失败笔记持久化并跨会话继承就够了，不必期待读取次数大幅下降。
