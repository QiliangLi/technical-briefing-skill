FastKVComp：KV压缩跑得不够快，省下的带宽就兑现不了

论文/来源：Beyond Compression Ratio: High-Throughput KV Compression for Disaggregated LLM Serving

分离式LLM serving里，KV cache是主要的跨节点通信对象。压缩能省通信，但压缩本身执行过慢会把省下的带宽吃回去。FastKVComp优化的不是压缩比，而是压缩管线的执行，让高带宽互连下KV压缩的收益真正兑现。

实际改了什么

实现在KVServe之上：把分布变换与量化融合成单个TileLang核，消除中间张量物化；压缩后端用可搜索的LC无损压缩替换nvCOMP。

关键结果

双节点200-Gb/s InfiniBand上，较原始传输JCT降低30.2%至38.6%，输出吞吐提升44.2%至62.6%（生成至多64 token）。指标维度偏窄：只有JCT与吞吐，没有TTFT、TPOT或P95，每个配置仅50个请求，模型质量也没有数字。

ARK：不动交换机，在端主机上给KVCache大象流预留路径

论文/来源：ARK: Avoiding Routing Collisions for KV Cache Transfer in Disaggregated LLM Inference

解耦推理的KVCache跨网传输是持续数百毫秒到数秒的大象流，ECMP哈希冲突会把并发流压到同一条spine链路。ARK用纯端主机软件做路径预留，不改交换机就消除冲突热点。

调度怎么判断

预留全在端主机完成：每台主机维护一份复制的spine预留表，新流到达时控制器选空闲spine，用预计算的源端口偏移让ECMP恰好哈希到它，再经低带宽控制信道广播预留。

关键结果

16GPU两层spine-leaf仿真里，ARK较ECMP把平均流完成时间最多降27.3%、P95最多降34.0%，平均TTFT最多降12.9%。引用时务必带上限定：全部是包级仿真、规模仅16GPU，收益集中在拥而未饱和区间，端到端TTFT是建模值。

MOIRA：按注意力覆盖度保留KV页，128k解码TPOT降2.2至2.5倍

论文/来源：MOIRA: Mass-Oriented Indexing with Ragged Attention for Long-Context Decoding

长上下文解码每生成一个token都要读全部KV缓存，卡在显存带宽上。MOIRA在vLLM里提供免训练的自适应稀疏解码：按注意力覆盖度逐层逐头决定保留多少页，精度保住、时延降下来。

缓存怎么处理

每个请求、层、KV头和解码步都用覆盖率规则，保留让估计注意力质量达到gamma的最小页集；自规划注意力核让线程块自行划分任务，整步保持在CUDA图内。

关键结果

RULER 128k、gamma=0.99时精度与稠密FA3持平，只读约30%的页，TPOT降低2.2至2.5倍；并发16时吞吐提高45%至51%。评估仅单GPU，没有跨节点KV传输、TTFT或网络数据；省的是带宽不是容量，高并发仍受显存上限约束。

HELIX：编译期动态规划，给每个算子挑异构加速器

论文/来源：HELIX: HEterogeneous LLM Inference with FleXible and Fine-Grained Partitioning

异构LLM推理大多沿用固定的prefill/decode或注意力/FFN切分，难以随负载与硬件调整。HELIX在编译期对计算图做动态规划，为每个算子选定宿主，目标是压低解码时延。

怎么做的

搜索以画像得到的算子执行与通信代价、设备能力与内存约束为输入，配Pareto剪枝；只覆盖部分算子的加速器也能以子图执行器接入vLLM。

关键结果

对比注意力/FFN切分，Bamba 9B单步解码约1.7-3.2倍、Llama 8B约2.2-1.1倍；大批量时传输时延掩盖收益，多数划分退回GPU。结果是画像估计的单步解码时延而非端到端指标，3DCIM与DRAM-PIM多为仿真，3.5倍未经验证。

RECEIPT：命令先提问再行动，Agent却以为它做完了

论文/来源：RECEIPT: Measuring and Repairing the Return Assumption of LLM Agents in Web Service Operations

运维Agent普遍带着一个隐含假设：工具调用有界返回、动作已经完成。实际上命令常常先提问再行动，而测试的8个harness里7个把输入关掉了，于是11.5%的提示型调用没执行任何动作就返回0，Agent拿到的是假完成。这项工作把该假设测了出来并给出修复。

怎么做的

RECEIPT的修复做在工具执行链里：保持输入打开，从内核系统调用读出每个线程究竟在等什么，把输入与报告顺序建成自动机、性质经模型检验，再把真实进程状态回传给Agent。

关键结果

代价与收益都量化了：提问未回答会让任务token涨到2.9倍；换上RECEIPT后，mini-SWE-agent上跨5个LLM的虚假完成从34次降到9次，token还比普通终端少24.4%。作者自己提醒结论未必适用于其他harness与LLM，token数字出自Tripwire基准。

Pollard：每个语义步骤有唯一身份，严格回放不重入工具

论文/来源：Pollard: Governed Semantic Execution Trees for Framework-Independent AI Agent Control and Replay

Agent框架里执行、治理与回放各记各的账，最终答案追溯不到资源消耗与工具调用依据。Pollard给每个语义步骤一个唯一身份，严格回放时不重入被包装的操作，也为工具复用提供了完整性验证。

怎么做的

步骤身份由规范化输入、种类、尝试次数与父身份共同承诺；同一棵树既记录完成与拒绝，也记录资源结算。框架接入靠薄适配器，只包装选定操作、不翻译控制图。

关键结果

155次严格回放没有一次进入被包装操作，对照的参数键控缓存则产生930个祖先不安全别名；四个框架360对手工参照全部匹配，720棵树全过验证。它只测治理与完整性，不报告时延、token或成功率收益。

DeLoop：历史压缩把Agent逼进循环，自挖破环动作对来治

论文/来源：DeLoop: Repeated Actions as Self-Supervision for Long-Horizon Agents
为什么会这样

一个反直觉的起点：为了省上下文做历史压缩，Qwen3-8B的循环率反而从29.0%升到57.3%——长时程Agent会原样重发先前的工具调用，压缩让原地打转变本加厉。DeLoop从Agent自身轨迹自监督挖出循环与破环动作对，拿去做DPO。

怎么做的

偏好对的构造很干净：循环动作作负例，其后第一个破环动作作正例；挖掘只用动作与观测，不需要奖励、状态或裁判。

关键结果

Qwen3-8B在CodeGym的循环率从57.3%降到6.1%，成功率25.9%对25.1%基本不亏；步数降到4.67、token降47%，混入跨域偏好对后成功率到30.3%，但仍低于全历史的31.7%。它只针对完全重复的调用，走训练路线而非改Harness。
