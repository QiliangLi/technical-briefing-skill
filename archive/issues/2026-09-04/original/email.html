CacheRoute 用一张每周期刷新的路由表，把 KV 复用做进了请求路由

论文/来源：CacheRoute: Planned Prefix-Affinity Routing for Large-Scale LLM Serving
调度怎么判断

语义缓存服务的前缀亲和路由一直有个矛盾，按缓存命中路由容易把请求挤到同一台机器。CacheRoute 先按测得的每 key 速率从高到低准入暖前缀，给每个 key 封顶单目的地负载，再用 LPT 调度放置，路由表在一个控制区间内固定，用缓存稳定性换掉逐请求重映射。

关键结果

Llama-70B 测试床在 p99 不超 3.5 秒的约束下维持 176 QPS，是 Preble 的 2.3 倍。消融很有信息量，只加亲和，命中明显上升但负载不均衡急剧恶化；只有 LPT 放置把不均衡压住之后，容量才真正上来。

可以怎么验证

路由层确实能大幅提高 KV 复用而不必然制造热点，前提是亲和、复制封顶、放置三件套一起上。内部路由改造可以先做影子回放验证再启用。

Pallas 把切换当成截止期来准备，KV 迁移中断从秒级压到毫秒级

论文/来源：Pallas: A Proactive KV Cache Migration Framework for LLM Inference in AI-RAN

AI-RAN 场景里用户在基站间切换，KV cache 跟不上就是秒级服务中断。千 token 的 KV 就有约 256MiB，300Mbps 链路下传输压力很大，硬传不可能。Pallas 把切换当作目标侧的状态准备截止期，在准备触发点把 token 序列切成稳定前缀和演化后缀，目标侧本地 prefill 重建前缀，源侧继续推理并流式传后缀块，切换时拼合两段立刻恢复解码。

关键结果

三组模型平均中断降到 154 到 324 毫秒，比目标侧恢复最多低 89.7 倍。实验室 trace 驱动评测，依赖移动性预测，多用户争用留作未来工作。前缀重建加增量流式的分解，可以直接搬到跨集群 KV 迁移与预取策略上。

HiSparse 把完整 KV 放主机内存，稀疏注意力解码吞吐最高快 4.7 倍

论文/来源：HiSparse: Scaling Sparse-Attention Decoding with Hierarchical KV Cache Management
缓存怎么处理

稀疏注意力模型每步只选少量 token，但全集必须可寻址，显存还是被长上下文撑爆。HiSparse 的分层方案是每请求完整 KV 历史放主机内存，解码足迹由一块小而固定的 GPU 缓存限定，融合 CUDA kernel 在解码图内完成命中检测、LRU 替换和主机取数，对跨层共享选择的模型还做精确逐层预取。

关键结果

三族稀疏注意力在多代高端卡上峰值吞吐最高提升 4.7 倍。GLM-5.2 的 32K 输入场景里，全 KV 基线在高并发下 TTFT 涨到 275 秒，HiSparse 保持 1727 tokens/s。短上下文低并发时它只剩 IO 开销，要按场景禁用，约 27% 的结构性同步 IO 无法预取。

等人工审批的请求一挂几小时，KV 该留还是该扔有了定价方法

论文/来源：Adaptive KV Retention for LLM Agents at Human-Approval Timescales

现有代理 serving 系统研究的都是秒级工具暂停，人工审批一等就是几分钟到几小时，量级完全不同。这篇工作量化了这个场景的两头代价，KV 强制留在显存里，活跃请求 goodput 损失 41%；直接驱逐，恢复时延涨近 10 倍。

怎么做的

控制器用 GPU 机会成本统一定价。挂起时 KV 立刻卸到主机内存，host 层在无限保留和按负载过期两种策略之间，用一段独立校准的等待样本回放比较总成本，选便宜的分支冻结，运行时只需要当前负载一个输入，不用预测每个请求等多久。

关键结果

人类尺度审批负载下，活跃 goodput 比 vLLM 基线高 23% 到 51%，对另外两个对比系统的提升幅度更大。等待分布依赖校准样本，负载漂移后要重新校准。内部带审批流的代理服务可以直接套这套定价和分层。

轨迹级安全监控被证明必然漏掉跨迭代攻击，循环层要留非衰减状态

论文/来源：Safety Does Not Compose: Non-Decaying Loop State for Autonomous LLM Agents
为什么会这样

结论很硬。对证据分散在多个迭代里的攻击，任何只在单轨迹内看数据的监控，真阳性率等于假阳性率，跟模型多强没关系，因为需要的证据根本不在它看的窗口里。直觉上的修补，带一个几何衰减的风险分，也不够，耐心对手等过的冷却期是一个不随时长增长的常数，付一次就够了。

LoopHarness 在内层 harness 外面运行，用中介化提交和仲裁者检测底线，把期望的未授权不可逆动作数约束成不随任务时长变化的常数，其中主要部分由免模型规则裁定，验证器完全合谋也照样成立。

可以怎么验证

对内部长时程流水线的含义很直接。单次审批、单轮扫描这类按轨迹重置的风控对碎片化攻击是结构性失效的，有据风险证据要以非衰减形式留在循环层，不可逆动作的预算用规则而不是模型来裁。

KV 压缩后答案还是对的，推理链可能已经坏了

论文/来源：Does Accuracy Equal Evidence? Reasoning Faithfulness under KV Cache Compression
为什么会这样

这篇审计的发现值得每个用 KV 压缩的人看一遍。只取最终答案和压缩方法都答对的样本，驱逐式方法的推理链退化率普遍过半，SnapKV 到 64.8%，而量化对照 KIVI-2bit 只有 4.2%。结论是失败主要来自丢失推理轨迹的访问权，而不是内存变少本身。

失败形态也有规律，答案优先的合理化占比从全量的 58% 涨到压缩后的 94%，模型先给对答案再编一套说辞。sink 类方法会过度保留开头的错误锚点，attention 类方法会过度保留长得像结论的尾部内容。压缩部署的验收指标里应该加上答案链一致性和扰动忠实性，不能只看准确率。
