KVCache里的冗余副本是还没吃到的收益，改布局和掩码就行，不必先造新内核
vLLM原型利用Gemma 4全局层键值可互推，每KV头每token只存一行值，由原版分页内核经两个交叠视图读同一显存，无需新内核，16位下每请求解码KV内存降至原来约七成，与原布局算术仿真逐位一致。华为在昇腾上用树注意力让每个token只关注自身、祖先路径与共享提示，并静态分配KV区，大束宽下算子总时延降到vLLM的约37%，靠掩码KV管理补齐。前者依赖这种等宽K=V结构，后者只在单一推荐负载上验证。

XM-Sparse把稀疏注意力的KV卸载到scale-up内存池，支撑更大并发

论文/来源：XM-Sparse: High-Throughput Sparse-Attention LLM Serving over Scale-up Memory Pools

稀疏注意力服务仍要保留全量KV历史，HBM容量直接卡住并发。XM-Sparse把KV与K-index缓存激进卸载到scale-up内存池，用互连带宽换HBM容量，支撑更大的batch。

缓存怎么处理

动态选中的KV用TMA检索，与注意力计算做tile级流水融合；K-index的全量扫描改由GPU发起DMA预取，并让位于按需检索与模型通信。

关键结果

matched batch下，DeepSeek-V3.2与GLM-5.3的TBT较PCIe基线分别降35.8%和45.8%，吞吐较HiSparse最高4.52倍。scale-up内存池来自模拟，没有真实X-Mem硬件；TTFT与分位时延未见，实验限于单节点。

Parallel Prompting让同一长文档的多问解码只读一次KV

论文/来源：Read Once, Answer Many: Parallel Prompting for Shared-Context LLM Inference

对同一份长文档提多个问题时，逐问成请求让每个解码步都重读整段文档KV，解码因此受显存带宽限制。Parallel Prompting把P个问题并成单请求里的P条并行流，每步只读一次共享文档。

怎么做的

注意力核内按流编号的掩码保证各答案只依赖文档与自己的问题；解码步形状固定并捕获为CUDA图，SGLang中只增加了约80行代码。

关键结果

CodeLlama-7B的长文档多问负载上，较原生SGLang在A100快3.7倍，A6000快5.9至6.0倍；GQA模型Qwen2.5为1.3至1.9倍。它面向共享文档请求预先已知的离线批量场景，在线服务还需调度器集成，实验也只有单GPU与单一注意力后端。

接收方拿不准再等消息，不确定性低就跳过并独立作答

论文/来源：Safe to Omit, Worth Omitting? Keeping the Answer and Cutting Latency When an LLM Agent Skips Another's Message

多智能体系统里，接收方要等助手消息才能继续，延迟随之增加，而oracle上限也不能证明消息真有用。这项工作在接收方不确定性低时直接跳过消息，答案改动率以高概率不超过5%。

怎么做的

一次探测前向在不读消息的情况下估计接收方的不确定性，低于认证阈值就独立作答。阈值在无标注校准问题上以精确有限样本检验选定，没有阈值过关就回退为始终通信。

关键结果

2000道封存题上跳过39.9%的验证者调用，12.80分增益保留12.55分；批大小1至32的文本策略平均延迟较基准低310至1728毫秒，P99不劣于基准。认证的KV缓存路径精度低于接收方单独作答，MMLU-Pro上两个策略未能认证，批次变化需按实际批大小重校准。

KVPath沿深度把KV连成路径，GQA缓存最多减68.65%

论文/来源：KVPath: Connecting Key-Value Representations Across Transformer Layers

Transformer每层独立缓存全量KV，显存随长度与深度线性增长。KVPath把token的KV沿深度连成路径，首层存全量，后续层只存低维增量，参数匹配下GQA缓存最多减少68.65%。

怎么做的

第0层缓存全维基KV，其余各层由自身隐状态生成低维delta KV并更新上层状态，提供残差与滚动两种变体。

关键结果

参数匹配时GQA缓存减少67.19%至68.65%，ResGQA困惑度低2.88%至3.48%；MLA缓存降到标准的45%至47%，困惑度不高于基线。规模也别高估。实验止于约0.6B参数，没有专用注意力内核，结果是解析的缓存体积，没有实测服务吞吐。

AnyS1让一个4B小模型接管Agent的可枚举决策

论文/来源：Thinking Fast, Anywhere: One System-1 for the Decision Points of Any Agent Workflow

Agent每步都调大模型，成本随轨迹增长一路攀升。AnyS1把技能编译成工作流，交给一个校准过的4B System-1，可枚举的决策一次前向作答，置信不足就回退大模型，用低得多的成本维持任务效果。

怎么做的

编译时把技能步骤分成确定性、可枚举、开放生成三类节点，用容器任务的执行轨迹训练一个4B指针小模型。运行时一次前向回答可枚举决策，置信不足即回退大模型。

关键结果

DeepSeek-V4.1-Flash骨干下，SOPBench通过率84.3对55.2，ALFWorld成功率95.5对82.8，成本分别省91%和88%。回退门是命门，关掉后ALFWorld成功率跌到40.3；阈值校准每个工作流约需50次开发运行，代码场景没有测。想搬进自家流水线，可以先试这个校准回退门，以约95%的大模型一致率作门槛下放决策，编译与校准成本则要先摊销。

AHE-Beta不跑基准，靠模拟用户工单和证据门禁进化Harness

论文/来源：Agentic Harness Engineering Beta: Requirement-Centered Evolution of Agent Harnesses

用基准分挑Harness改动，隐含的用户需求看不见，还容易选中任务特定的补丁。AHE-Beta把选择压力换成模拟用户工单，合并走证据门禁，只进化Harness，不动底座模型。

怎么做的

每轮由50种人设的模拟用户使用Harness并提交工单，分诊与开发等角色把工单拆成PR，只有附上运行日志等证据并通过评审的PR才合并，全程不跑基准。

关键结果

38个留出任务上pass@1从21.9%升到33.3%，超过Claude Code的27.2%；用户评分从2.59升到3.04，执行token少40.8%。进化只覆盖32个场景、6轮与单一模拟器，总算力与显著性未报，延迟和工具调用数据也没有。

Agent工具调用重试的故障注入实验，去重与恢复是两件事

论文/来源：Idempotency Is Not Recovery: A Fault-Injection Study of Language-Model Agent Tool Actions

语言模型Agent的工具调用被中断后重试，动作可能重复生效。目标端幂等能去掉重复，却答不上故障之后结果到底成没成。这份未评审预印本用单主机故障注入实验证明，去重与恢复是两种独立的性质，并量出了防护的代价。

怎么做的

受控运行时组合五项机制。派发前做授权校验，动作台账带稳定标识，目标端按标识做幂等，崩溃后向目标查证对账，证据封存之后才确认完成。

关键结果

200对崩溃重放中，完整配置的重复效应为0/200，较简基线各自117/200。代价不小，运行窗口吞吐约为故障开放基线的七分之一。范围也窄，单主机合成基准，针对工单类操作，代码编辑Agent不在目标内，多主机与生产可靠性未验证。

Vestrum用1到10条长episode逐组件改进现成Harness

论文/来源：Vestrum: Learning the Verification, Retrieval and Structure of Agent Harnesses from a Few Long Episodes

现成Harness部署者往往改不动，长任务能拿来学习的episode又只有几条。Vestrum按失败类别逐组件改进Claude Code这类现成Harness，只要1到10条长episode。

怎么做的

它读完整的原始轨迹，把失败归入可识别的类别，只改出错的那一个组件，可能是自验证、检索视图、分解或记忆操作。泛化过滤器会拒绝照搬开发任务里的事实。

关键结果

Claude Code在Terminal-Bench 4 Hard检查点的通过率由63.7%升到70.3%，这是在8个留出任务上测出的，测试成本为1.03倍，没有任务下降。测试模型未公开；与GEPA相比省的是任务执行数，不是总token。

CodeReel按内容寻址精确复用帧，缩短视频Agent的构建等待

论文/来源：CodeReel: Accelerating Code-to-Video Agents with Exact Frame Reuse and Blocking-Aware Scheduling

代码生成视频的Agent每次构建都是阻塞调用，成片中位耗时11分钟，超过三分之一花在构建上。CodeReel用内容寻址的精确帧复用加检查先行的调度，把等待较温热流水线缩短36.3%。

缓存怎么处理

每帧以归一化到光栅器的求值绘图命令为键，同键即精确复用，跨版本与时移编辑都有效。调度上先跑检查，渲染以低优先级并行启动。

关键结果

真实Agent里每次构建的中位等待降到Rebuild的0.62至0.67倍；时移编辑下只重绘43.9%的帧，全部成片与从头渲染逐帧一致。范围限于2D程序化绘制，3D帧只渲染不复用，生成式素材不在范围内。
