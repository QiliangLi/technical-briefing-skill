把上千个 LoRA 放进 CXL 近存内存池,解码时延降 6.6 倍

论文/来源：PLoRA: An NDP-Enhanced Pooled-Memory System for Cost-Efficient Multi-LoRA Serving
怎么做的

PLoRA 把 LoRA adapter 与 KV cache 放进 CXL 池化内存,由近存计算单元返回归约结果,GPU 用自己的 load/store 取结果,host 不介入。单张 H100 服务 1,000 个 adapter 时,解码时延比 S-LoRA 低 6.6 倍。

为什么会这样

带宽结论值得单独记住:链路 32 到 64 GB/s 就饱和,继续加带宽没有意义;长上下文场景想靠加带宽追平,需要 12.2 到 18.6 TB/s,不现实。剩余链路带宽应该换成池容量。大部分结论来自模拟,且依赖带设备侧计算的 CXL 3.1 组网,对我们内存语义方向的带宽与容量取舍是直接输入。

vLLM 的磁盘 KV 加载快 2 倍,秘诀是少而大的异步读

论文/来源：Building py-kvcache: A Performance Characterization of External KV Caching for vLLM with NVMe SSDs
怎么做的

py-kvcache 优化 vLLM 外部 KV 缓存的加载:预加载信号取自调度器等待队列,磁盘读取与计算重叠,80k token 场景比 LMCache 快 2.0 倍。它还加了一个 break-even 准入门,低于门槛的前缀不再加载,把外部缓存当成部署级准入决策。

为什么会这样

加速的来源值得记住:更少、更大的异步传输,而非更高的带宽,两者实际都只有约 24 到 26 GB/s。同一份测量也给出反面结论,H100 上平均请求低于 break-even 点时,外部缓存反而无益。结论绑定所测硬件与版本,只测了 FP16 单输出 token。

可以怎么验证

break-even 准入门可以直接搬进内部分层缓存的准入判断,传输时机与粒度的结论也能用于离线缓存调优。

harness 进化之后,别再用专家全轨迹去微调模型

论文/来源：模型与执行框架协同进化：在策略专家纠错让弱模型在模仿失效处追赶

Salesforce 的实验给了一个反直觉结论。先用自动进化把弱模型的 harness 调好,7 项企业任务从 29.2% 提到 78.0%;此时用更强专家的完整轨迹做 LoRA 模仿,弱模型反而在全部 7 项任务上回退,平均掉 14.9 分。原因在模型与 harness 的匹配被破坏,模仿让模型学会了专家的规划风格,却没学会执行这种风格的能力。

怎么做的

替代方案是在策略纠错。一个元级 MLE 智能体在弱模型自己的 rollout 里找出走错的那一轮,专家只重写这一轮,其余步骤原样保留。大约 400 行修正样本,质量裁判从 3 个候选里挑一个,训练不足 1 小时,成功率再涨 1.7 个点到 79.7%;规划类失败保持在 1.8%,模仿路线的这项会涨到 14.6%。

可以怎么验证

顺序在这里比方法本身重要。先进化 harness,再做在策略纠错,避免全轨迹模仿。这条原则可以直接套进我们自己的 harness 迭代与模型微调排期。

论文 · 2026-08-14

321 token 的调试上下文,值 18.1 个百分点的修复通过率

论文/来源：Evaluating Agentic Code Repair Capabilities in Distributed Systems

USC 的 DDBENCH 回答了一个我们一直想量化的问题:给编码 Agent 喂多少定向调试上下文,值多少通过率。基准收了 60 个开源分布式系统的真实缺陷,每个缺陷跑两次,唯一区别是有没有挂载一个平均 321 token 的上下文包,里面是日志、追踪、竞态报告或代码探索笔记。

关键结果

10 个模型的聚合通过率提升 18.1 个百分点,收益不对称,弱模型主要涨通过率,强模型主要省 token,整体平均 token 消耗约减半。最难案例集上模型间通过率相差 61 个百分点,15 对顶级模型有 9 对被显著区分,说明分布式调试考察的是单进程基准测不出的推理维度。收益随缺陷搜索空间缩小而衰减,最简单的一层只剩 7.1 个点。

需要注意

实验只用 mini-swe-agent 一个脚手架,上下文包没有做内容级消融,不知道日志和追踪各自贡献多少;忠实的上下文偶尔也会把模型带偏。但把定向上下文注入当作独立于模型升级的加速杠杆,这个结论已经足够扎实。

只学正常样本,也能盯住 Agent 工作流里的异常

论文/来源：Skynet: Workflow-Level Anomaly Detection for Agentic AI via Semantic and Structural Modeling
怎么做的

Skynet 把多智能体执行记录整理成有向工作流图,节点和边携带角色、工具、状态与因果顺序,再用 K=150 个仅含良性流量的 k-means 模式库建模正常流形。语义上下文和依赖结构联合建模,执行一旦偏离流形就报警。训练从未见过攻击或失败,所以没见过的失败模式也落在同一条判别规则里。

关键结果

在 Agent-SafetyBench 和 AgentErrorBench 两个基准上,它在 0.89% 误报率下召回 100%,17 类内在失败(包括幻觉、约束忽视这类细微错误)全部覆盖;混合场景 F1 94.07,高于各图异常检测基线。常开监控最怕误报,这个低于 1% 的误报预算是它最实际的卖点。

需要注意

边界也清楚:与良性工作流高度相似的异常会漏,间接提示注入的召回只有 74%,作者自己说需要内容级检查互补;时延只有定性描述。要用在内部,前提是我们的运行时能暴露结构化执行记录。
