华为FlashOffloading：主机DRAM持有权威KV副本，30毫秒TPOT下服务1M序列

论文/来源：FlashOffloading: Low-Latency KV Cache Offloading for Long-Context LLM Serving

长上下文推理卡在HBM容量上。FlashOffloading让主机DRAM持有权威KV副本，并按阶段切换驻留粒度：prefill用四层滚动HBM缓存逐层回载并与计算重叠，decode用16k热缓存，反向稀疏索引把缺失查询并入top-k过程。

关键结果

在32卡Ascend910C与GLM-5.2上，prefill吞吐最高提升1.38倍、decode最高1.91倍，512k与1M序列仅在双向卸载下可服务。代价与前提：吞吐提升以TPOT恶化为换，decode卸载依赖模型原生稀疏性，也未报告跨节点KV传输指标；评估KVCache感知网络调度的增值时，可拿它当纯内存侧基线。

StrataFlux：按重要性从内存层级补精度位，量化精度回血、速度基本保住

论文/来源：StrataFlux: Memory-Hierarchy-Native Low-Bit LLM Inference

2到4比特的权重与KV cache量化省内存但伤精度；把高精度退到慢层又拖慢解码。StrataFlux只为主干的信道和token组从主机RAM或SSD流式补取高精度位，用提前或滞后距离让传输与计算重叠，参数在给定减速预算内自动选定。

关键结果

2比特权重下Llama-3.1-8B混淆度9.46到8.40，保留量化吞吐的95.4%；Qwen3-8B配2比特加2/2 KV量化，AIME从11.0%升到47.1%。传输只到单机RAM或SSD，无跨节点与TTFT、TPOT数据；统一内存平台批量补位开销最高25.4%。

BasisKV：一个共享低秩潜变量，同时压KV缓存与张量并行通信

论文/来源：BasisKV: Value Latents for Communication and Key Routing

已有低秩KV压缩只优化缓存本身，张量并行下注意力输出仍按全宽通信。BasisKV用单个共享的Value低秩潜变量把三件事一起压：每卡注意力输出先投影成低维潜变量再经保源AllGather通信，低秩因子对完整输出联合优化，压缩后的Value缓存兼用于Key路由。

关键结果

8卡L40S上，Llama-3.1-8B张量并行端到端最高1.42倍于稠密，TTFT从34.6秒降到24.7秒；LongBench平均46.91对47.02仅略降。实验全部单机，无跨节点KVCache传输，AllGather通信字节数也未披露。

多智能体交接降负载：SelectKV只压新增KV，HyLaMAS共享双通道状态

论文/来源：Selective and Hybrid-State Communication for Latent Multi-Agent Systems

Harness自进化的总分提升靠不住：16个进化Agent全部有得有失

论文/来源：Beneath the Surface: What We Overlook When We Talk About Agent Evolution
为什么会这样

冻结模型权重、只让Harness自我进化，总分确实会涨——但这份实测拆开看：16个进化Agent全部在新增1到15个任务的同时丢失2到10个，多数可靠性提升还推高部署成本。只凭总分做选型或验收，会把有得有失误判成纯改进。

怎么做的

论文把进化过程分解为选择、分析、变异、门控等七个算子，用四种配方在MiniSWE与Codex两种Harness上重复评测，并对任务做配对统计。最刺眼的一条：四个父代池里最高分的父代都不是最大改进者，原选择规则的命中率低于随机。

可以怎么验证

实验仅在隔离基准环境运行、只测GPT-5.4单一模型，成本增幅与AGE改进幅度未给数值。但验收方法可以直接改：配对统计新增与丢失任务、跟踪部署成本，选版前先回放一次选择决策。

预注册实验：独立上下文验证者检出植入缺陷95.4%，构建者自测85.1%

论文/来源：Who Verifies the Builder? Toward Independent Assurance for Agent-Produced Software

Agent生成的软件有个验收难题：构建者自测不再独立，自己写的东西自己验，天然偏乐观。这项研究把验证移到构建平面之外的独立保证平面，并做预注册实验：新鲜上下文的验证者对46个植入缺陷检出95.4%，显著高于构建者自测的85.1%。

怎么做的

做法是先冻结一份人工批准的验证契约，再分两阶段验证：规范优先阶段只凭规范与公开接口检查；实现感知阶段读代码，用变异、属性与模糊测试补强证据；失败仅回传反例。

需要注意

限制要记全：契约、保证报告与人工发布环节未在实验中端到端检验，最终程序全部正确，发布门召回无法测得。另有几组数字：换供应商的验证者检出不升反平（85.1%）；发布门误拦正确程序从14/15个单元降到仅计有效测试的2个；独立验证每单元耗6.7万到12.6万token。验收门可借鉴独立上下文验证加反例回传，并把这笔token成本计入门的核算。

给智能体一份人类提案而非详细规格：LoLBench上最强者只解14%

论文/来源：LoLBench: Evaluating Coding Agents with Long-Horizon Proposals on Large Software Systems

现有代码基准都从详细规格出发，跳过了真实工程的第一步：把高层提案定位到大型仓库。LoLBench用100个人类提案配29个平均240万行的系统考全流程，每题约5000词提案加参考实现PR，用变异体审计的Fail-to-Pass测试加回归测试打分，测试只经由公共入口调用。28个智能体里最好的也只解决14%的任务。

关键结果

失败集中在感知而非实现：文件级巡检精度只有16.1%到36.3%；附上由参考实现衍生的文件树与API规格后，解决率升16到22个百分点、最高到34%——差距主要在仓库定位这一步。

需要注意

解读限制：文件树与API规格来自参考解、含预言信息，不等于可自建的索引；每智能体仅尝试一次，也只考功能正确性。我们的判断是瓶颈在感知而非实现，可以先投仓库定位与索引这类前置grounding；验收缺失是首要失败模式，值得补显式验收门。

LowRam在测试时压缩KV缓存：4倍近无损，叠加量化驱逐可到26.9倍

论文/来源：LowRAM: Low-Rank Keys and Amortised Values for Composable KV Cache Compression at Test-Time
怎么做的

KV缓存随上下文与批量线性增长，限制解码吞吐。LowRam按头用两层MLP拟合key到value的映射，只保留按误差排序后误差最大的少量token残差；再配跨层低秩key压缩与选择性重建，元学习初始化把适配降到2次梯度更新。

DMT用固定循环记忆替代KVCache：推理状态恒定，代价是质量落后Mamba

论文/来源：Dynamical Memory Transformer: Selective Recurrent Memories with Constant Cost Attention
怎么做的

DMT用固定记忆单元的循环状态加注意力读取替代KVCache：每个单元是复数对角循环矩阵的动力学系统，按输入相关的leak rate在旧状态与候选状态间插值更新，解码器仅以注意力读取各单元当前输出。推理状态从此恒定，不随长度增长。

为什么会这样
