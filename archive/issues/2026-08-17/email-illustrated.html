Genesis把长时程开发的记忆留在项目里

论文/来源：Persistent Recursive Worlds Enable Autonomous Software Evolution

长任务通常靠维持一个长期Agent进程来保持连续性。Genesis换了一个持久对象：不是进程，而是项目版本、路径和历史。

实际改了什么
每个有限生命的Agent只在由已接受版本和仓库路径定位的局部世界中工作。跨路径任务通过递归委派转移，父级中介决定是否接受结果；上下文则来自版本化的CONTEXT.md和Git历史。
关键结果
系统从空仓库构建了25万行Rust C编译器，运行超120小时、经历千余episode，成本仅44美元并通过c-testsuite；MESA重写后，六个负载的中位加速为1.55到6.87倍。
结果来自单机单次运行，缺少重复成功率和完整人工干预记录，但把项目状态作为持久层的组织方式值得试点。

AutoDesign让harness也进入持续优化循环

论文/来源：AutoDesign: Meta-Harness Optimization for Long-Horizon Agentic Design

很多长视界设计任务都依赖固定harness。AutoDesign让元优化器根据rollout反馈修改harness本身，并用开发集表现控制是否接受。

怎么做的
外层每轮只修改五个功能组件之一，只有训练集提升且开发集不下降时才通过接受门；每次优化都保存检查点，既能回滚，也允许人类用自然语言定向引导。
关键结果
论文转海报基准中得分78.32，比Claude Design高7.45分；harness让七种Agent配置的平均分从54.99升至67.39。
实验只覆盖论文转海报场景，也可能陷入局部最优，但“可优化harness加接受门”可直接借鉴。

CommitKV用工具提交事件判断哪些缓存已经完成使命

论文/来源：CommitKV: Lifecycle-Aware KV Cache Compression via Commit Transitions for Multi-Turn Agents

多轮ReAct轨迹不断增长，普通快照式逐出无法区分暂时休眠的信息和已经无用的信息。CommitKV把工具调用的提交转换当作语义信号。

怎么做的
系统比较工具提交前和观察结果并入后，删除某个token页对输出的影响。影响从高转低的页面会经过联合测试后退休，始终低影响的休眠页则保留；键值和绝对位置使用同一索引集。
关键结果
在4096预算下，三种骨干模型的平均准确率都位列压缩方法第一；Qwen3-14B达到46.54，最强基线为26.69。2048预算下，它比最好基线高22.24个百分点。
小预算下仍不及不压缩，且只测了单机轨迹，但提交转换很适合用于长时程Agent缓存策略。

ZhuLong用沙箱试出未文档化的EDA API行为

论文/来源：ZhuLong: Execution-Grounded LLM Agent for EDA Scripting with Offline API Self-Exploration

EDA脚本API长尾严重，文档也经常缺失。ZhuLong让Agent在沙箱里检索、检查、执行，再根据错误逐步修正。

怎么做的
系统基于Cline-CLI构建，用三个统一MCP工具串起检索、文档检查和执行。遇到未文档化API时，它会在沙箱中改变参数并观察结果，再把发现的约束写回增强文档。
关键结果
158项任务上，Pass@1为78.5%，纯LLM基线为23.6%；自探索让每项任务的工具调用减少22.1%，语义检索比grep高12.7个百分点。
GUI场景关闭自探索且不重试时，Pass@1降至60%和50%；把踩坑经验固化为文档的思路仍值得迁移。

即使固定随机种子，LLM输出仍可能不一致。CoRun发现，多数GPU内核要求位置不变，而不是整个批次都保持不变。

实际改了什么
系统把预填隔离出来，并用固定形状批解码和补齐维持逐位置数值语义，再通过CUDA graph执行，不需要重写内核。吞吐比批不变方案高15-324%。

补齐会浪费计算和显存，且与连续批处理动态准入存在冲突，但它显著降低了确定性的实现门槛。
