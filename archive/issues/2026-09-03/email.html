蚂蚁AInfer-PD:不走P/D分离,把复用做通信安全

论文/来源：AInfer-PD: Communication-Safe In-Place Prefill-Decode Multiplexing for Distributed MoE Rollouts

agentic RL的rollout里,新prefill和进行中的decode天然混在一起。常见的两条路各有代价:分离部署要独立设备池加KV跨池传输;原位复用省了传输,但在大规模MoE下,P和D两组集合通信会以不一致的顺序交叉,直接死锁。AInfer-PD选了第三条路——修好通信安全,继续复用。

实际改了什么

两个关键机制。一是跨rank协调P与D集合通信的顺序,消除attention副本上发现的设备推进环;二是给DeepEP的两条路径各自独立的缓冲、计数器和QP区间,让P与D的专家通信互不踩踏。rank对齐的segment turnstile逐轮放行P段,保证顺序一致。

关键结果

单节点prefill密集负载下,完成时间比关闭复用的同引擎低7.1%到22.5%,比SGLang低24.8%到32.9%;双节点最高降35.3%。两次真实RL运行累计rollout时间降了17.6%。要注意的是,decode-only场景开启复用反而掉6.7%吞吐,应该条件启用。

跨模型搬KV cache不用重训:闭式映射的存储、时延、构造成本同时降

论文/来源：CacheBridge: Efficient Cross-Model KV Cache Transfer

多模型系统交接对话时,接收方通常要把共享前缀重新prefill一遍,因为KV cache是模型私有的。CacheBridge沿用了闭式仿射映射的思路,但把每个目标KV头的来源限制到一个架构索引匹配的源头上,系数直接少了8倍。

关键结果

效果分三笔账。质量:救回了基线方法在两个Ministral 3迁移方向上大幅失准的问题,平均保留率从59.43%升到97.57%。时延:mapper应用最高提速3.0倍。构造:500序列的mapper构建从92.63秒降到8.63秒。

需要注意

作者把边界划得很清楚:只在同家族、KV头数匹配的稠密GQA模型上验证过,跨家族迁移和稀疏、线性注意力架构都没试;测的是即时延续质量,多轮使用后的误差累积没测。想引入的话,这两个边界就是我们先要补的验证。

GDN和KDA的状态也能量化了:9.9bit保精度,TPOT降一成

论文/来源：DAMP: Decay-Aware Mixed-Precision Recurrent-State Quantization

线性注意力模型用固定大小的递归状态替代大部分KV cache,但状态本身常以FP32存储,Qwen3.6-35B在大批下光状态就要占十几GB,状态更新在解码时延里占近四分之一。DAMP是第一个系统研究这类状态训练后量化的工作,先确认了均匀量化不行——INT8就掉点,INT4接近归零。

怎么做的

两个经验发现支撑方案:量化误差集中在少数关键通道;通道的衰减强度排序跨任务稳定。于是离线校准一次,给高风险通道高精度、其余INT8,布局推理期不再变。

关键结果

9.9bit下的AIME得分83.65,贴近FP32的85.46,而均匀INT8只有44.21。系统层面状态存储降69.1%,KDA更新内核提速2.01倍,整模型TPOT最多降10.9%。

小模型的置信度能当路由信号:多模态请求留在边缘还是升级云端

论文/来源：Pro-Router: Token-Aware Progressive Model Routing with Adaptive Edge-Cloud Collaboration for Efficient Multimodal LLM Inference

Pro-Router解决多模态推理的成本问题,思路是逐token看小模型的采样概率:置信度高就本地交付,低就升级到云端大模型。路由信号本身只要2到3毫秒,比让模型自我验证再决策的方案快28倍。

关键结果

服务管线较既有路由方案吞吐高75%以上。对广域部署重要的是时延鲁棒性:单向网络时延注入到1000毫秒,管线仍保持未延迟吞吐的90%到96%。最大配置下扩展到5.8到6.9倍。

Agent工作流改需求时别整体重跑,REVISE只重算受影响的那部分

论文/来源：REVISE: Validity-Guided Recovery for Online Revisions in Agent Workflows

真实编码Agent的工作里,修订经常在上一版还没跑完时就到了。REVISE的做法是把修订的变化量与已记录的数据、控制依赖求交,影响沿执行中的DAG传播,然后只停掉真正失效的工作,保留已验证有效的进展,重算被波及的部分。

关键结果

在未修改的LangGraph和LLMCompiler应用上,较整体重启减少模型调用40.6%到56.0%,较从冲突点重算后缀的做法少31.3%到43.6%,历次执行没有一个过期输出。真实轨迹分析显示这种并发并不罕见:重叠响应的p95达到56.55秒。

需要注意

两个现实约束。单请求的关键路径改善有限——p50只快5.9%,省下的算力要在多副本争用时才变现成吞吐;细粒度溯源覆盖不足时会回退到完全恢复,覆盖50%时就有60%的请求走回老路。溯源机制的投入成本值得我们先算一笔账。

skill束不是prompt,是目录——按目录的思路给它瘦身

论文/来源：SkillZip Pro: Execution-Aware Dynamic Compression of Progressively Loaded Skills for Self-Evolving Agents

SkillZip Pro把生产环境的Agent技能当成它本来的样子:一个渐进加载的目录束,根文档常驻、引用和脚本按需加载。压缩是跨文件进行的——根文档或环境契约已经写过的内容,从引用文件里删掉,但每个入口的路由保持可达。

关键结果

在一个生产内容审核skill上,束内token少了约四成,任务配对的每run运行时token降10.4%,决策质量没有统计退化。最有用的发现是根token的杠杆效应:删一个根token约等于删五六个按需引用token。反过来,无保护的激进压缩会丢两位数的精度点。

需要注意

把上下文组装当成数据库查询来做,token省三成、调用省两成

论文/来源：ContextPipe: Database-Inspired Context Assembly for Long-Horizon Agents

长任务Agent每轮prompt里放什么、按什么顺序、什么时候压缩历史,这些决定在生产系统里通常散落在各处。ContextPipe的主张是把这整件事做成一个正式的运行时层:数据源有目录和schema,组装是缓存感知的确定性优化,每次调用留下EXPLAIN ANALYZE式的执行轨迹。

关键结果

在SWE-bench Pro的一个长程子集上,总prompt token降了30.1%,LLM调用降17.2%。代价要说清楚:缓存命中率从95.6%掉到86.3%,fresh token翻倍。作者给出了一个计费模型——只有当缓存token价格超过fresh的14.5%时,结构化组装才在账单上也占优。

可以怎么验证

RAG的离线KV缓存做完INT4量化,答案还是对的,依据已经不对了

论文/来源：Faithfulness Is Not Free: Auditing Offline KV-Cache Quantization in Retrieval-Augmented Generation
为什么会这样

这份审计研究测了一个此前没人测的东西:RAG系统预计算的检索文档KV缓存,量化之后回答的忠实性还剩多少。结果值得警惕——INT4量化后,在仍然事实正确的答案里,超过90%的忠实性变化是负向的,也就是说回答不再被检索证据支持,而准确率指标完全看不见这件事。

关键结果

INT8基本无损。INT4的危害随检索噪声和块数增长:RGB上与BF16的幻觉差距随检索块数增加扩大到数倍。INT4还是唯一出现退化输出(重复循环、无输出)的配置。存储收益方面,INT4约3.6倍,低于名义值,因为每块要存scale和零点。

可以怎么验证

结论一句话:量化缓存上线前要单独做忠实性验收,准确率指标不看这件事。我们如果要做RAG的离线缓存复用,这份三信号审计方法(幻觉检测、NLI蕴含、LLM裁判)可以直接搬。

论文/来源：DASC: Decay-Aware State Compression for Hybrid Linear-Attention Serving
缓存怎么处理
