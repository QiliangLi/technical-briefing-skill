KVStream：不预测带宽、只认完成事件，把两级存储读满

论文/来源：KVStream: Adaptive Parallel Storage Management for KV Caching in Large-Scale LLM Serving

长上下文服务的KV缓存超出内存后，存储读取进入推理关键路径。KVStream把读取改成跨NVMe与并行文件系统的完成驱动调度，不预测带宽即逼近聚合带宽上界并降低TTFT。

调度怎么判断

每步读取成批发起、写回滞后于前向计算；每个数据块在两个存储层各存一份，先空闲的层立即认领下一批未读块——路由只依据完成事件。

关键结果

70B离线吞吐47210 tok/s，是LMCache的1.48倍；32B在线平均TTFT从31.1秒降到13.0秒，静态分层对照恶化到122.1秒。复用集能放进主机内存时收益消失，全量复制带来2倍写放大，TPOT与TTFT尾部分位未见报告。完成事件驱动的多路径带宽聚合值得借鉴，只是它调度的是节点存储I/O，不涉及跨节点KV网络传输。

跨一条广域网做PD解耦的实测：中位TTFT从0.11秒涨到4.24秒

论文/来源：InferSlice: A Reference Architecture for SLO-driven LLM Inference over a Telco Wide-Area Network

现有推理框架面向紧耦合数据中心。InferSlice在英国国家级电信广域网上实测跨单跳WAN做Prefill/Decode解耦：中位TTFT从0.11秒升至4.24秒，TPOT基本不变。

关键结果

9毫秒RTT下解耦使中位TTFT升至4.24秒、P99达19秒，吞吐从406降至297 token/s；惩罚不随RTT增大，作者归因于每请求KV交接的固定开销。

EdgeFlow：按带宽逐层决定KVCache是传还是重算，迁移最多快45%

论文/来源：Efficient KV Cache Migration for Geo-Distributed LLM Inference in Collaborative Edge Computing

协同边缘推理在节点断连或过载时必须迁移有状态KVCache，而云端方案假设高带宽同构互联。EdgeFlow按带宽逐层分配直接传输与激活重算，在500Mbps均值带宽的实测平台上，迁移时间较直接传输最多缩短约45%。

怎么做的

KVCache可从各层更小的中间激活重算得到，EdgeFlow据此逐层决定重算与直传比例并让计算与通信重叠，再用2近似算法联合选择迁移目标节点——50个候选节点决策仅需3.22秒，暴力搜索需325分钟。

需要注意

它只报告迁移时间与决策开销，缺少TTFT、TPOT等端到端指标；100Mbps低带宽下优势基本消失。跨节点迁移应感知链路带宽与节点算力来决定传输量，低带宽场景可评估传输与重算拆分，但这组数据不回答时延收益。

SARIA：按复用历史选择性写SSD，写入量较全量双写少五成多

论文/来源：SARIA: Persistence-Aware KV Caching with Coordinated DRAM--SSD Reload for LLM Agents

代理长前缀重用迫使KV缓存扩展到SSD，全量双写按推算每天每GPU约103.7TB。SARIA用复用历史选择性落盘并协调重载路径，兼顾SSD寿命与TTFT。

缓存怎么处理

按DRAM驱逐与复用历史决定哪些KV块写入SSD；SSD命中后延迟部分晋升，协调器为GDS直读与DRAM读取分配GPU入站带宽。

关键结果

消融中平均TTFT较串行基线降5.8%~6.4%，加协调器后尾部传输再降11.0%~17.8%；摘要另称SSD写入较全量双写少57.1%~58.9%。仅单机DRAM-SSD路径，无TPOT、吞吐与跨节点网络结果，双SSD配额失配时协调劣化15.8%——分层之上叠加传输带宽协调确有增量收益，但配额必须匹配有效路径带宽。

动作定了就别再问一遍模型：HarnessMM复用工具决策，token最高降87.93%

论文/来源：HarnessMM: Recursive Self-Improvement for Harness Token Efficiency

harness在每次工具反馈后都重新调用推理，哪怕下一步动作其实已经确定，重复审议持续消耗token。HarnessMM用护栏式决策复用替代这些重复回调，token大幅下降，成功率大体保持或提升。

怎么做的

控制器把精确动作、参数与因果依赖存成可执行决策图；工具回执一到就激活持久决策、经原生接口执行并移除已注册的慢回调，遇到新语义或证据不足时回退原模型。

关键结果

HumanEval上DeepSeek成功率从71.43%升至85.71%、token降87.93%；Codex成功率持平、token降29.54%。注意token节省不等于时延或能耗节省，消融里禁用决策图执行要多解4题，主结果也只覆盖短编码任务；自建harness引入这套复用时，须配套逐任务配对评测与回退路径。

论文/来源：SPECMEM: Accelerating Agentic Tool Calling via Live Memory Management

工具调用Agent的时延大头来自逐词自回归解码。SPECMEM用按用户在线更新的调用记忆提供投机解码草稿，输出与贪心解码等价，实测解码加速最高1.74倍。

缓存怎么处理

每用户维护容量48的LRU调用存储，按余弦相似度取最近邻作草稿，验证通过后写回记忆；对声明有不可逆副作用的调用，验证完成前推迟执行。

关键结果

预热后平均接受token数较冻结存储基线在BFCL提升27%、Seal-Tools提升34%；副作用门控在模拟中把错误不可逆执行降为零。但用户重复行为由基准任务模拟生成，预热覆盖全部任务时增益缩至约2%，也未在代码Agent轨迹上验证。我们要在工具执行链复用已验证调用做投机解码的话，必须配在线写回与副作用声明门控——一次构建的静态缓存会随新任务持续失效。

CARE：轻量批评者按置信度在云端与本地间切换控制权

论文/来源：Know When to Escalate: Critic-Guided Adaptive Execution for Cloud-Local Embodied Agents

云端大模型决策慢、本地小模型易错，固定分工与无状态路由无法随难度调整。CARE用轻量批评者按置信度在本地与云端间切换控制权，以约三成云端调用接近纯云端成功率。

怎么做的
