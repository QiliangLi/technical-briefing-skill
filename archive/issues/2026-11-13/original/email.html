TKNP解耦权重放置与KV归属，八节点可用KV容量约为DP的5倍

论文/来源：Decode Token Parallelism: Memory-Efficient Distributed Attention Parallelism for Scalable LLM Decoding

长上下文、高并发的解码场景里，数据并行靠复制权重挤占KV容量，张量并行又把all-reduce推上跨节点网络。TKNP把这两件事拆开：权重放置归权重放置，KV归属归KV归属，八节点的可用KV容量约为DP的5倍。

怎么做的

模型按平衡的layer block分布到各节点；每个节点只对自己请求的本地KV算attention，跨节点流量只剩scatter/gather。

关键结果

在vLLM上实现、最多64块H100：较DP吞吐最高2.06倍；八节点较DCP为1.53倍，加上双活root微批达到1.7倍（405B模型、32K上下文）。评估只覆盖InfiniBand互连的H100，小batch或短上下文时通信开销可能反超收益。

KV内存约束下的调度有了最优性背书：cμ规则加回填

论文/来源：Asymptotic Optimality of $cμ$-Rule for LLM Inference Scheduling under Memory Constraint

单张GPU上，推理请求调度实际受限于KV缓存容量。这项工作用流体模型证明cμ优先规则在这种内存约束下渐近最优，并在生产轨迹回放里大幅降低平均时延与TTFT。

怎么做的

cμ规则按代价乘以有效服务率给请求排序，这个速率综合了算力、访存带宽与容量；准入检查保证未来各步的KV占用不超限，backfill变体绕开不可行请求继续接纳别的。

关键结果

压缩To-B轨迹上，cμ-backfill平均时延9.47秒、TTFT 2.56秒，vLLM默认调度是35.49秒与28.77秒，输出吞吐基本持平。对比都假设输出长度精确已知并按回放评估，预测误差的影响未测；场景也限于单GPU。

KV取回前先验一张误差证书：VERKV少搬47倍主机数据

论文/来源：Verify Before You Fetch: Reliable KV Cache Compression for LLM Inference

KV缓存超出显存之后，全量搬运主机缓存会让解码被PCIe支配，查询无关的压缩又容易崩塌。VERKV在取回前先验证误差证书：证书过关就不访主机，不过关再补取，vLLM解码提速1.6倍、主机传输少47倍。

怎么做的

PoissonComp按基础压缩器的得分做泊松抽样，挑出驻留GPU的token；KVFetch为注意力评估(ε,δ)证书，满足容差就直接本地算，不满足才回主机补取。

关键结果

32K上下文下质量为稠密注意力的90-100%，显存降8-32倍，每token只取回2-23%的缓存；vLLM解码较全量offload最高提速3.1倍。不过ε0=0.5时比稠密驻留慢约6倍，2位草图在严格容差下违反δ，而且只有单卡PCIe卸载的证据。

原生FP4解码：算法与内核一起改，精度几乎不掉

论文/来源：BitDecoding-FP4: Native FP4 KV Cache Decoding via Algorithm-System Co-Design

长上下文服务里KV Cache挤占显存，朴素的FP4量化平均要落后BF16达8.5个点。这项工作用算法与内核的协同设计，做出了几乎无精度损失的原生FP4解码，解码吞吐大幅提升。

怎么做的

算法侧用双FP4残差表示查询，欠流感知的概率缩放避免E4M3把小概率归零，离群感知的键量化抑制通道离群；内核侧让注意力全程跑在FP4张量核上。

Qwen3-4B上NVFP4精度67.27，BF16 KV为67.69；256K上下文TPOT快1.81倍，64并发单卡峰值吞吐是BF16的2.4-3.0倍。证据全部来自单节点Blackwell的内核与显存实验，TTFT、P95与跨节点KV传输都未评估。

修一个issue烧掉几百万token？把定位与验收搬到函数级流图上

论文/来源：FlowPlan: Reducing the Token Cost of Coding Agents with Abstraction-Guided Planning and Verification

Claude Code式的agent修一个issue动辄消耗数百万token，基线里96-98%其实是缓存重读。FlowPlan把故障定位、修复规划和验收都搬到函数级流图上，六个设置里token全部下降，解决率没有显著变化。

怎么做的

抽象单位是单个函数的控制流图和数据流图：先在图上定位故障，把修复表达成显式的图增量，改完之后重建同一张图核对结构变化，最后再做整体验证。

关键结果

对原生基线，token比为0.32-0.94倍，六个设置里五处显著，解决率无显著变化；Haiku 4.5在Verified上从3.41M降到1.09M。证据也有清楚的适用范围：只有Claude Code和单一厂商的两个模型、每实例单次运行，端到端时延与流图构建更新的成本都未见证据。如果只改一处，优先改编辑后的结构化复查——73-75%的降幅来自那里。

203GB查表不再钉死主机内存：按每层预取期限分层放置

论文/来源：Placing LLM Lookup Tables by Per-Layer Prefetch Deadlines

DeepSeek-V4.1那张203GB的查表，过去只能整张钉在主机内存。SlackTier按每层预取期限把表分层放到NVMe与RDMA，主机内存降到34GiB，每token时延至多只增1.4%。

怎么做的

表放到第二节点经RDMA读取，批128/256的步时间与主机DRAM持平；一份表还能供两个实例共享，时延差距在2.2%内。远端读取目前只测了同集群RDMA，WAN场景未测。

几分钟的突发就能让Agent前缀缓存陷入持续崩溃

论文/来源：Bursts That Outlast Themselves: Persistent Degradation in Prefix-Cached Agent Serving

闭环Agent会话靠前缀缓存控制成本。这篇论文发现，几分钟的请求突发就能触发一场自持续的崩溃：突发结束后命中率停在约10%，积压还要持续增长约70分钟，常规的等待与限流都难以恢复。

为什么会这样

崩溃的机理在Little定律：回合响应变慢让更多会话并发驻留，前缀总量超出共享KV池，前缀在下一回合到来前就被逐出，于是几乎每回合都全量重算，代价还随上下文继续增长。

关键结果
