HAWK：GPU预填充、NPU解码，KV Cache直传时顺带完成布局重排

论文/来源：HAWK: Heterogeneity-Aware KV Cache Transfer for Efficient GPU-NPU Phase-Disaggregated LLM Inference

用GPU做预填充、NPU做解码的解耦推理，卡在跨设备KV Cache传输上：不仅要搬数据，两边布局还不一样，传完得重排。HAWK把布局适配并入传输路径，让异构直传的性能逼近同构GPU。

怎么做的

它基于Mooncake打通GPU到NPU的RDMA直传，在传输过程中同步完成布局变换以匹配NPU的要求；NPU端预留布局感知缓冲，数据到达后解码可以直接使用。

关键结果

1280MB传输时，GN-HAWK的延迟约为主机中转的14.7%，与GPU直连相差不到1%；以90% SLO达成为基准，请求速率至多低7.69%，成本效率最高1.72倍。验证范围有限：仅Tenstorrent p150a加Llama 3.1 70B、单实例规模，成本按市价折算。对我们的P/D解耦选型，值得先量传输路径——它而非解码调度决定TTFT的上限。

UlaCache：给稀疏注意力的KV历史做统一逻辑寻址，8卡TP下87.5%历史是副本

论文/来源：UlaCache: Unified Logical Addressing for Sparse LLM Serving

稀疏注意力每步只读选中的位置，但完整KV历史必须全程可用；GLM-5.3的8卡张量并行下，87.5%的历史分配成了副本。UlaCache用统一的逻辑地址空间，把推理引擎与KV的物理放置解耦。

缓存怎么处理

逻辑地址映射横跨GPU池与CPU内存，KV搬动只更新映射、不重写数据；稀疏选择时先查本地GPU缓冲，只传缺失的条目；预取放在独立的CUDA stream里，与计算重叠进行。

关键结果

在匹配内存预算、开启投机解码的条件下，8×B300的峰值解码吞吐达到HiSparse的1.73倍（DP）与2.51倍（TP）；替换路径上PB-LRU比朴素LRU快1.5至2.3倍。所有传输都限于节点内CPU-GPU与卡间IPC，没有跨节点实验，TTFT、P95与网络利用率也未报告。

PN-Mix：按查询-键交互选通道做混合精度KV量化，约2.26比特逼近FP16

论文/来源：PN-Mix: Pair-Norm Guided Mixed-Precision Key Cache Quantization for Efficient Long-Output LLM Inference

长输出解码下KV缓存线性增长，Qwen3-8B的FP16缓存在40GB上批量或长度稍大就OOM；均匀压到2比特又伤长思维链精度。PN-Mix按查询-键交互挑选重要通道，平均约2.26比特就能接近FP16。

怎么做的

通道对的重要性取查询侧与键侧平均对范数之积，预填充期算一次、解码期复用；显著的通道对用3比特，其余用1比特。

关键结果

四个模型的基准平均分与FP16差距都在1分之内，且优于Kitty；Qwen3-8B在40GB内可跑8倍生成长度或5.5倍批量。证据全部来自单GPU实验，没有TTFT、TPOT或网络侧数据；显存充裕时FP16同批量吞吐反而更高。

三星VS-Flash：闪存段经CXL共享给主机与设备算力，向量检索吞吐最高提升57.4倍

论文/来源：VS-Flash: Harnessing Vector Search with Computational Memory-Semantic Flash

向量数据超出主机DRAM之后，Milvus的SSD服务会因缺页换页而吞吐下降、尾延迟上升。三星的VS-Flash把闪存段通过CXL暴露出来，交给主机与设备算力共享执行，让批量吞吐与尾延迟同时改善。

怎么做的

设备先把活跃段以1GB为单位从闪存预取进板载DRAM；主机CPU与板上的RISC-V核经CXL共享同一地址空间；请求按批次大小分流，预取窗口随负载自适应调整。

关键结果

三个十亿级数据集上，批量吞吐较原生Milvus平均提升36.8倍、最高57.4倍；SIFT100M混合负载下，小批量请求的p99最多降低24.8倍。看数字要留意：36.8倍是摘要级汇总，逐数据集结果未见；基线只用了72核中的8核，设备侧核数与容量也未披露。

RiseHarness：模型权重不动，用重复运行的成败证据迭代改进运行框架

论文/来源：Harness Self-Evolution for Long-Horizon Terminal Agents

长程终端智能体重复跑同一任务，结果并不稳定，而运行框架（harness）的有效性又依赖模型自身行为。RiseHarness把模型权重固定住，只用重复运行得到的成败证据迭代改进harness，并设验收门：必须完整评估、通过率超过基线才采纳改动。

怎么做的

改进循环从轨迹入手：同时记录智能体轨迹与运行时监控轨迹，定位同一配置下时而成功时而失败的翻转任务，再结合手册与其他框架的设计生成提案；提案经可选的行为检查、小规模筛选试验与全量复评，达标后才采纳。

关键结果

结论很实用：两个模型用各自的harness，在两个基准的Pass@1与Pass4上都优于换用对方的harness，互换要损失约2.3至9.0个百分点——harness收益按模型分化，不宜直接跨模型复用。证据有缺口：主结果表与图6不可见，图7数值取自柱状图打印标签，改进循环的token与时延成本未报告。

数据库Agent生产实测：多数损失发生在模型与服务器的传输边界

论文/来源：What Stops a Small Language Model From Driving a Database Agent

「小模型带不动Agent」通常被归因于推理能力不足，这项生产实测给出了不同答案：多数损失发生在模型与服务器之间的传输边界，只改服务器端就能显著移动成功率，模型、提示与采样全程未动。

怎么做的

做法是在生产SQL客户端的agent模式里跑39个本地模型加1个托管对照，共8199次运行；把损失归入能力、传输、时钟、验证四类，并额外捕获被拒工具调用的参数，用来定位服务器侧缺陷。

关键结果

75.7%的模型归因损失来自已经调用过工具的运行——工具都发出去了，问题出在边界。五处仅服务器端的修改，让六个模型在30个格中移动了6至21格。外推要谨慎：结论来自单机、单数据库与单一harness，传输高于能力的排序也只在74.5%的重采样中成立。评测本地模型时应先排查两个混杂：无上限的上下文驻留与swap——本例中一个3B模型限制上下文后从0/5变成5/5。

APEXA：工具调用被网关静默丢弃后，模型会汇报从未运行的结果

论文/来源：APEXA: Execution-Integrity Enforcement for Multi-Agent LLM Automation of Synchrotron Data Reduction

LLM网关会把解析不了的工具调用静默丢掉，模型随后汇报一条从未运行过的命令的结果，而对话级指标仍把这轮判为成功。APEXA在服务器侧加了一层确定性工具层，把这条伪造路径堵死。

怎么做的

执行完整性守卫逐条检查输出：没有已执行调用支撑的结果会被拒绝并强制重试；解析器容忍跨模型的格式漂移；另有五项EPICS预检。全部逻辑落在服务端代码里，不依赖模型自觉。

关键结果

在50个场景×4个模型的仿真电机控制对抗测试中，工具层0/200违规，纯提示词基线15/200；系统还在APS真实束线数据上以单条指令完成端到端归约。局限：只测单顺序推理循环，未涉及并行或投机执行；电机安全仅对仿真IOC验证，也没有任务成功率、时延与token数据。代码Agent同样面临调用被丢弃后伪造测试或构建结论的风险，值得在harness侧引入这类确定性验收门。
