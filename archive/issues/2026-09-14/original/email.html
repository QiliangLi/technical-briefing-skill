LMCache v0.5.5 默认隔离 IPC，CacheBlend 支持 PD 分离

论文/来源：LMCache/LMCache v0.5.5
实际改了什么

这个版本把多进程 KV 传输默认改为隔离 IPC，KV 缓存通过原生 CUDA IPC 注册，配合 VMM 封装和信号量事件后端，部署不再需要 hostIPC 和共享 /dev/shm。协调器改成可持久化、可插拔，CacheBlend V3 成为唯一的混合路径并在引擎内支持 PD 分离。

实际改了什么

传输计时被分解成 gather、DMA 和预留三段，L1/L2 命中有了归因和 Prometheus 计数。平台矩阵扩展到 Trainium、昇腾、MUSA、XPU 和 ROCm，P2P 共享改用 Mooncake 传输引擎。发布说明里没有基准数字，性能收益要等上游评测或自己验证。

可以怎么验证

传输计时分解可以直接拿来定位跨节点 KV 传输的开销构成。隔离 IPC 是部署形态变化的信号，建议评估一下升级成本。

RefactorPlatform 用 AST 验证门受控评测仓库级重构 Agent

论文/来源：RefactorPlatform: An Open-Source Harness for Controlled Evaluation of Repository-Scale Refactoring Agents
怎么做的

平台固定环境、显式变化模型、执行模式和提示明确度四个轴。每个任务跑在隔离工作区里，diff、token 和完整转录都被记录。Python 任务用 AST 级单元测试把关，Java 任务加抽取、编译、测试和 RefactoringMiner 门，通过率反映的是行为保持的变更，顺眼的 diff 不算数。

为什么会这样

可以怎么验证

HiKV 两级筛选同时压缩 KVCache 的 Token 和元素

论文/来源：HiKV: Hierarchical Importance-Aware KV Cache with Hardware Acceleration for LLM Decoding
怎么做的

HiKV 先按 Token 重要性筛选，再只在保留 Token 内部挑重要元素，形成两级压缩。可重构的 Importance Sorter 和片上 Scoreboard 维护排序，TISG 与 K/V 布局减少外部访存。

关键结果

四个模型的系统仿真显示，在平均精度损失不超过 1% 的约束下平均解码加速约 5.70 倍，平均只保留 vanilla 外部 KV 访存的 13.94%。

需要注意

结果来自算法、系统和 16nm 后布局仿真，没有 GPU 或集群实测，评估是单请求 batch=1、4096 Token Prefill，没有覆盖长序列 P95 和跨节点一致性成本。它可以作为跨域 KV 传输前的压缩候选，但压缩计算、序列一致性、命中率和 RTT 都要我们实测，本地访存缩减不能直接当成跨区域加速。

MeClear 用 Shapley 归因找出拖后腿的 Agent 记忆并做最小清除

论文/来源：MeClear: Cooperative Game-Theoretic Attribution and Risk-Aware Memory Clearance for Long-Horizon LLM Agents
怎么做的

留一筛查抓不住多条记忆互相掩盖的情况，MeClear 在留一之外加采样合作 Shapley 归因，把效用分摊到交互的证据上，再按归因排名做查询范围内的最小清除。清除之后先在裁剪过的上下文上验证任务能否恢复，不永久改写记忆库。

关键结果

十个长对话记忆池上任务恢复率 82.3%，比留一基线高 25.5 个百分点。目标记忆排名 @2 达 88.1%，提升并非来自过度删除。

需要注意

故障是程序化注入的，验证集含合成成分；清除是会话内的抑制，跨会话治理没有覆盖；Shapley 采样的开销也没有报告在线时延。归因、最小清除、恢复验证这个闭环可以参照设计跨域缓存的失效策略。

KVDiagnosis 把 KV 压缩的失败拆成可诊断的证据

论文/来源：KVDiagnosis: A Diagnostic Benchmark for KV-Cache Compression in Long-Context Language Models
怎么做的

它给每个方法设置组合单独建逐源 FullCache 对照，挑出原本正确、压缩后错误的行，避免任何压缩器定义别人的测试集。25 个方法归入五个机制族，统一记录格式把配对输出连到缓存、似然、注意力和解码四类测量。

关键结果
