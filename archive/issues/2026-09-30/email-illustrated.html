01
KV分层的收益取决于“何时再用”，不是“放在哪一层”
分层 KV 的设计重心正从放在哪一层转向何时再用。PulseInfer 的实测显示召回 I/O 才是真瓶颈：碎片传输把 PCIe 有效带宽压到个位数 GB/s，把召回当调度对象后解码吞吐最高近五倍。TempoKV 证明暂存时机本身就是资源——命中先记元数据、到点才提交，快层受保护容量省下六到九成而吞吐不掉；DPS 更把权重显存变成 KV 的弹性来源，突发负载下吞吐成倍提升。三条线共同指向：复用时序的建模比层级选择更值钱。
相关解读：PulseInfer：稀疏KV卸载的真正瓶颈是召回I/O · TempoKV：KV暂存的关键是时机而不是越早越好 · DPS：权重显存不必是常量，可以借给KV块
02
Agent负载的上下文复用是真的，但载体不是前缀
蚂蚁的生产纹迹给了口径：工具调用后首个后继请求的缓存输入占比中位约 99%，但逻辑兄弟请求几乎从不真正并行，复用会跨任务发生。Tessera 的刻画补上缺口——agent 记忆注入的 token 有七成多在非前缀位置复发，常规前缀缓存碰不到，把检索层变成控制平面后平均 TTFT 降数倍。StateTape 证明另一半在写入侧：按代码写入事件失效与检索，Claude Code 持有的 token 有七成多并不需要。缓存和调度该按执行结构组织，而不是按会话结构。

03
scale-up域上，通信要计入“占用谁的资源”
MoK 在 NVL72 上发现为 scale-out 优化的 MoE 训练常跑不过 PyTorch 加 NCCL 的朴素基线：按算子选 push 或 pull 方向、再消除 CPU-GPU 同步后，层级加速最高两倍多，Cursor 的生产训练栈只换 MoE 实现就多了四成吞吐。HOCCL 用实测把通信的 SM 占用摆上台面，峰值约占一成，DMA 卸载释放近 10% SM 换来端到端小幅提升。VarioPath 则在无 NVLink 的 PCIe 集群上按负载规划 AlltoAllv 路径。单跳域和异构互连上，通信方向、SM 预算与传输路径都成了要显式付费的资源。

HeteroFold：异构agent之间直接传KV，别再传文本

论文/来源：Prefill-Free Cross-Family KV Cache Transfer for Heterogeneous Multi-Agent LLMs

不同角色用不同模型族的多 agent 系统里，文本通信意味着每个接收方都要把共享上下文重新 prefill 一遍。HeteroFold 在收发双方都冻结的前提下做跨族 KV 传输：token 对齐、深度聚合、跨头混合处理掉分词、层数与表示的差异，再用输出感知的校准保证接收方的行为不变——缓存重构误差低不等于行为保持，这是它和前作的关键差别。

关键结果

六个传输方向、四个长上下文基准全部最佳；32K 上下文跨族传输比原生 prefill 快 10.7 倍，比已有免 prefill 基线快 1.18~1.47 倍，多 agent 基准上与文本通信持平。评估限于若干模型对，更大规模泛化未展开。

AugTree：RL重放阶段，prompt只算一次

论文/来源：Splitting Prompt Prefill from Response Replay for Context-Parallel Long-Context LLM Post-Training

RL 后训练每轮要把一组采样响应在更新后的策略下重算，每组共享一个长 prompt 扇出多条响应分支，标准上下文并行会逐分支重算或反复搬运同一段 prompt KV。AugTree 把重放拆成两相位：prompt prefill 只算一次，响应分支在有界通道上调度；在线规划器按负载形态二选一通信语义——响应占优就通道内轮转 KV 分片，prompt 占优就把 query 移到驻留属主，且 prompt 态全程保持可微。

关键结果

四个后训练负载、最多 64 加速器上，训练步时较动态 CP 平均快 1.18 倍（最高 2.23 倍）、较无复用基线快 7.08 倍，通信量较 MegaN 最多降 16.2 倍。面向训练侧重放而非 serving。

TempoKV：KV暂存的关键是时机而不是越早越好

论文/来源：TempoKV: Timely Staging of LLM KV Caches for Memory-Semantic Flash

在内存语义闪存层级里，逻辑命中不等于数据就绪：按需暂存会把 SSD 时延暴露给请求，立即暂存又长期占着受保护的快层容量。TempoKV 的做法很克制——命中先记成纯元数据声明，不发起 I/O 也不预留容量；控制器把运行时估计的剩余时间和存储侧估计的就绪时间对起来，到点才授权提交并预留容量保护到检索完成。

关键结果

每请求受保护的快层 byte-time 比立即暂存少 63%~91%；快层容量从 100 GiB 降到 25 GiB 吞吐几乎不变，较 LMCache DAX 配置的 p95 TTFT 最多降 48%。TTU 估计假设目标已就绪，属于自引用投影，评估绑定 CXL 实现形态。

StateTape：编码Agent的上下文应该跟着代码写入变

论文/来源：StateTape: Action-Conditioned Evidence Lifecycle Modeling for Long-Horizon Coding Agents

编码 agent 的上下文维护习惯按时间或长度裁剪历史，但代码是被 agent 自己一次次改写的：一次写入会让持有的记录过时、让仍有效的记录显得多余、也让下一步需要的调用方代码缺席。TraceBench 在真实 Claude Code 编辑点上量化了这件事——持有 token 的 73.4% 并不需要，需要的 token 有 58.5% 缺失，而且浪费随编辑数持续增长。

怎么做的

StateTape 把仓库建成符号级代码图，每次写入记录被改变的符号并提名可能被证伪的记录，一个小型 manager 负责驱逐过时项、沿调用边向外检索缺失证据。六个 agent、三个基准全部拿到最高 resolve rate，manager 开销只占主 agent token 的 0.4%~4.7%。基准是银标签且限于单一 agent，迁移性未验证。
